## 已实施（P0 A/C + 部分 D 判定）

1. **F-01 终止原因贯通**（`server.js` + `public/app.js`）
   - `callAIStream()` 记录上游 `choices[0].finish_reason` 与 `[DONE]` 是否出现；缺字段保持 `null`。
   - `onFinish` 回调带回 `finish_reason / observed / requested_max_tokens / stream_terminated_normally`。
   - `/api/ai/write_stream` 的 `done` 帧新增上述字段与 `generation_status`（`PROVIDER_STOP / OUTPUT_LIMIT_REACHED / EMPTY_OUTPUT / STREAM_INTERRUPTED / USER_CANCELLED / PROVIDER_BLOCKED / UNKNOWN_TERMINATION`）。
   - 前端 `streamAIDirectWrite()` 保留 `generation` 元数据；`complete:true` 只代表收到 done，不再代表章节完整。
2. **F-03 伪分段故障文案**（`public/writing-quality.js` + `app.js`）
   - 质检跳过按真实 `reason` 映射：`unparsed / channel_unavailable / long_text_engine_unavailable / over_single_request_limit / cancelled / 未知原因码`；日志附 `reason_code`。
3. **F-04 篇幅诊断不再误判**（`classifyChapterLength` 委托纯函数）
   - `OUTPUT_LIMIT_REACHED` → `truncated`（即使字数已够也提示可能截断）；
   - 质检 `skipped` / `unknown` → `unverified`，**不得**判“短但完整”；
   - 结果弹窗新增 truncated/unverified 两种真实提示。
4. **F-02 边界保持**：`unparsed` 仍返回 `{skipped:true, reason:'unparsed'}`，不伪造 issues、不冒充 pass；修复循环只消费真实 issues。
5. **蓝图门禁（最小版）**：`writing-quality.js` 新增 `blueprintStatusOf`，把 `length_status` 与 `blueprint_status` 分开：
   - `truncated` / 质检跳过 / unknown → `UNVERIFIED`，`ready_for_normal_delivery=false`；
   - 质检 issues → `MISSING_REQUIRED_BEATS`，`unresolved` 保留真实问题；
   - pass → `VERIFIED`（仅此情况可正常交付）。
   前端记录 `ai_write_blueprint_status` 并把结果交给结果弹窗。**注意：这不是方案 §4 的完整 `required_beats` 账本/逐条证据门禁**，只是把"未验证/截断"与"质检缺情节"分开的最小落点。
5. 新增 `public/writing-quality.js`（UMD 纯函数）并在 `index.html` 装载。
