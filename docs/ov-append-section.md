## 追加：2026-09-14「🐞 运行追踪」改动重审（4 处失误）

来源：novel-studio 新增「🐞 运行追踪」功能后的自审重审。修复后验证：后端 api-test-suite 108/108、前端 frontend-test 19/19、TypeScript 精确检查 0 条。
完整报告：`novel-studio/docs/run-trace-review-2026-09-14.md`

**本轮最核心的一条教训**：我把「导出了 API」当成了「功能已完成」，导致用户明确选定的一项机制实际是死代码，而测试全绿给了我虚假的完成感。

### 失误 1（严重）：实现了接口却从未接线 → 用户选定功能实际未交付
- 现象：`debug-trace.js` 导出 `bumpTool()`（高频函数只累计次数+总耗时），`server.js` 也 import 了它，但**全仓库 0 处调用**（诊断：外部引用 1，仅 import）。
- 影响：需求澄清时用户明确选的是「分层追踪：主干全量 + 高频工具函数只记次数与累计耗时」，实际只交付了「主干全量」一半。更糟的是 README 已经写了「高频工具函数只累计调用次数与合计耗时」——把未实现的能力写进了文档。
- 根因：① 写导出时想的是"以后有需要再调用"，收尾没做「用户选定项 → 调用点」对账；② 测试套件没有覆盖这条路径，全绿造成虚假完成感。
- 修复：① `server.js` 的 `prepare()`（真高频热路径，一次操作上百次）接入 `bumpTool`，缓存命中记 0 耗时、未命中记实际耗时；② `/api/debug/ops` 本来就返回 tools 聚合表但前端从未展示 → 追踪页新增「高频函数累计」折叠面板；③ 补断言 I3y/I3z。

### 失误 2（中等）：心跳超时余量太小，把「切到别的标签页」误判成「页面已关闭」
- 现象：前端每 10s ping，后端 `checkStaleTracing` 超时 20s（仅 2× 余量）。
- 影响：浏览器把**后台标签页**定时器节流到约 1 次/分钟 → 用户切走查资料超过 20s，后端判定页面已关闭并停止录制；而界面按钮仍显示「● 录制中」→ **静默停止录制**，用户以为在录其实没录。
- 根因：按「超时 = 2× ping 间隔」想当然取值，没考虑浏览器对后台标签页的定时器节流；明明同一文件里既有代码就处理过这个节流（页面隐藏时跳过卡顿采样），我没把它联系到自己新写的机制上。
- 修复：`checkStaleTracing` 默认 20s → **90s**（9× ping 间隔）并写明取值理由；`server.js` 检查间隔 5s → 15s；注释固化这条约束。

### 失误 3（轻微）：4 个导出符号无人使用
`currentOp` 外部 0 引用（内部确有 4 处使用）→ 去掉 export 保留函数；`setHttpStatus`、`traceFilePath` 完全未使用 → 删除；`isRecording` 仅被 import 却 0 处调用 → 删除并从 import 列表移除。
根因：先写"完整 API 面"再补调用点，收尾没做「导出符号 → 外部引用数」对账。

### 失误 4（文档准确性）：方案里没做的项，文档只字未提
原方案写「明细落 JSONL + 摘要入 SQLite `debug_traces` 表」，实施时判断 JSONL 已自描述（session-start / op-end / session-end 三段含全部摘要），额外建表是重复存储，于是没建；但这个取舍只在对话里口头说了，README 只字未提 → 未来看文档会以为漏实现。
修复：README 明确写出「会话文件是自描述的…因此回看不需要额外的索引表」。

### 本轮新增的可复用收尾检查清单
1. **用户选定项 → 调用点对账**：每一项用户明确选择的机制，必须能用一条 grep 证明"有真实调用点"，而不是"有导出"。
2. **导出符号对账**：`导出符号 → 外部引用数`，0 引用且内部也不用的一律删。
3. **前端定时器 × 后端超时**：任何「心跳 + 超时」组合都要问「当前端被浏览器节流到 1 次/分钟时还成立吗？」
4. **文档 ≠ 方案**：方案里没做的项，文档必须写明原因，不能只字不提。
5. **测试全绿 ≠ 功能完成**：对"用户明确选过"的功能，先写断言再声称完成。

### 本轮确认「无需再怀疑」的结论（避免下轮重复排查）
- `search = traceFn('search', search)` 这类「同函数名重新赋值」：无 ESM 导出契约风险——被重新赋值的函数全在 `server.js`（入口文件，不被任何模块 import）与 `openviking-sync.js` 的内部非导出函数。
- `Object.create(stmt)` 包装 `node:sqlite` 的 StatementSync：只显式覆盖 `run/get/all/iterate`，其余方法走原型链落到原语句，安全。
- `/api/debug/*` 鉴权：受 `isLocalRequest` 保护（写方法需本机 Origin），会话文件名有字符白名单 + 前缀校验，路径穿越测试返回 404。
- `res.on('finish')` 在 `als.run` 内注册能取到正确状态码（断言 http_status=201）。
- `AsyncLocalStorage` 无法用 `enterWith` 从别的监听器跨界注入上下文，必须由请求回调自己 `als.run` 包住整段处理链（已实测：prependListener+enterWith 完全失效）。
