## 一、已修复的问题（本会话引入的失误）

### [R-FIX-1] `settings` 预算常量 12,000 字数学上不可达（server.js）—— 已修复

- **问题**：质量层 cap 合计 12,300 字（作品 900 + 长期记忆 2,200 + 召回 1,400 + 最近事件 1,800 + 伏笔 1,200 + 关系 800 + 红线 4,000），加弹性层下限（大纲 400 + 世界观 400）与角色卡（4,000）后，收敛循环的可执行下限约 **17,600 字**——旧常量 12,000 永远无法执行，是误导性数字。
- **为什么不能靠"收缩更多层"硬压到 12,000**：`novel_lookup` 关键词检索只覆盖词条/章节/角色/剧情线，**覆盖不到长期记忆与事件账本**；把这些层加入弹性收缩，在 OpenViking 宕机/禁用时就是不可查回的真实损失，违反「零损失」承诺。
- **修复**：`TOTAL_BUDGET` settings 分支改为 **18,000**（= 质量层全保底的可执行下限）。附带收益：1.2 万–1.8 万字的中等作品不再被无谓地把大纲/世界观压到 400 字。
- **文件**：`server.js`（`buildNovelContext` 内 TOTAL_BUDGET 与注释）。

### [R-FIX-2] 我最初写的冒烟断言 `assembled.length <= 12000` 是"小数据侥幸"—— 已双重修复

# 二次重审（2026-09-13 第二轮）

## 新发现并已修复：词条去重范围过宽，撞名即误删（零损失违约）

**[R2-FIX-1] `genWorkContextBlock` 的词条去重用 `ctx.includes('【标题】')` 对整块上下文比对**（`public/app.js`）：

- **问题**：角色卡层与召回层同样使用 `【名称】` 渲染格式。若某设定词条的标题与角色名相同（如词条「沈砚」），会被误判为"已在上文出现"而剔除——**词条正文随之丢失，且它不在"未选入清单"里，模型根本不知道它的存在**，违反零损失承诺。
- **第二个坑（修复过程中发现并规避）**：改用 API 响应的 `world_entries` 全量标题做去重也不对——世界观层可能被 3,000 字预算截断，响应里的条目未必实际渲染进上下文；对被截掉条目去重 = 词条"既不在上下文、又不在词条库"。
- **最终修复**：只在**世界观层实际渲染片段**（`【激活的世界观设定（优先级排列）】` 与 `【写作风格红线】` 两个已知层头之间）内做标题比对；红线恒为末层，边界确定。已用真实装配数据模拟验证：撞角色名的词条保留、撞世界观条目的词条去重、红线层正确切出。
- **验证**：`node --check` 通过；冒烟测试 32 组全通过；去重逻辑单独脚本实测 5 项断言全符合。

## 复核确认无误

- 上一轮 4 处修复（预算 18,000 / 大作品断言 / 工具描述 / 文档同步）复核无误：预算下限核算（17,100 字 + 标题注记）与 120 章 × 50 角色压力断言一致；
