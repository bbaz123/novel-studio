# 修稿合并 · 强制合并（2026-10-06，作者裁决）

> 作者原文：**「改成无论什么时候，只要是用户执行，就直接强制合并到正文」**

本文记录这条裁决、落地方式、仍然保留的安全网与回归门禁。
**它取代** [`docs/review-merge-empty-body-20261006.md`](./review-merge-empty-body-20261006.md) 里
"正文被改过 / 读不到就拒绝合并"的那部分语义（该文 §1/§2 的取证与根因仍然有效）。

---

## 1. 新契约（一句话）

**作者点「合并到正文」，就必须写进正文。** 不存在任何"被拒绝合并"的分支。
与 F3「旧内容是否保存？」同一条纪律（见 [`docs/adopt-guard-20261006.md`](./adopt-guard-20261006.md) §F3）：

> 可以**告知**、可以**留档**、可以**留痕** —— 但绝不**拦操作**。

## 2. 为什么删掉闸门（而不是继续修它）

R02.3 的原文保真闸门（"原文指纹不一致就拒绝合并"）在一天之内被证伪两次：

1. **空正文的章节必然被误拒**（2026-10-06 21:47 报障）：基线是空、当前也是空、指纹完全相等，
   却被 `!String(current).trim()` 当成"读不到"拦下 —— 详见前一篇文档的取证（活库可复算）。
2. 修掉那一处之后，"**正文在预览之后被改过就拒绝**"这条语义仍然站在用户的对面：
   作者点了却进不去，而唯一的出路（重新审稿、重新修稿）要再花几分钟与一次模型费用。

**关键事实：拒绝并不比覆盖更安全。** 被替换掉的那一版由服务端在采纳事务里
（`server.js` `saveChapterVersion(...)` → `chapter_save_versions`，`kind='manual'`）
存进本章历史版本 —— 覆盖是**可回退**的；而"点了没反应"会把作者逼去手工把预览里的段落
抄进编辑器，那会把旧段落与新段落叠在一起，**反而不可回退**。两害相权，取"强制写入 + 留档 + 如实告知"。

## 3. 落地（`public/app.js` `mergeReviewDiff`）

1. 删除所有拒绝分支：不再有 `toast('…已拒绝合并…')`，不再有提前 `return`。
   点一次 = 一次 `/novel/adopt` 写入（正文 + 勾选提案同一事务，幂等键 `operation_key` 不变）。
2. 指纹退化为**观测**：`baseChanged`（正文在预览之后变过）/ `baseUnreadable`（读不到），
   只用于两件事：
   - **告知**：成功提示里追加说明，例如
     「⚠️ 这一章正文在差异预览之后被改过，这次用它覆盖了它 —— 覆盖前的那一版已存进本章历史版本」；
   - **留痕**：客户端日志 `review_merge_overwrite`（含 work_id / chapter_id / base_unreadable），
     事后排查必须看得到"这一次为什么覆盖了"。
3. `revisionBaseArticle` 仍保留"取不到行 → 抛错 / 行在但正文为空 → 返回空串"的区分
   （上面两句告知文案靠它区分，见前一篇文档 §3 F2）。
4. **写入之后的本地收口失败不得谎报成"合并失败"**：`settleReviewMergeLocally` 单独 try/catch，
   失败只提示"本地界面基线没同步完（正文已在库里，刷新页面即可）"并记日志
   `review_merge_settle_failed`；正文已在库里这一事实不被改写
   （与 2026-10-05「把刷新失败报成合并失败」同一形状，本轮补上它的另一半）。

## 4. 仍然保留的安全网（都不拦操作）

| 安全网 | 位置 | 作用 |
| --- | --- | --- |
| 覆盖前那一版进历史版本 | 服务端 `/novel/adopt` 事务内 | 覆盖**可回退**（固定安全底线，与客户端无关） |
| 「旧内容是否保存？是/否」 | `settleOldContentBeforeOverwrite`（F3） | 编辑器里还没落盘的那一版：选"是"进历史版本，选"否"不留档；**两个答案都继续合并** |
| 合并前先落盘本页待写稿子 | `mergeReviewDiff` 开头的 `flushEditorSaves` | 让"旧稿进历史版本"兜住作者手里那一版 |
| 明确告知 + 留痕 | 成功 toasts / `review_merge_overwrite` | 覆盖了什么、为什么，作者与日志都看得见 |
| 跨章提醒 | 差异预览与成功提示 | 这份修稿属于哪一章、当前看的是哪一章 |
