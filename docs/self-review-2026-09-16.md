## 一、本轮新发现并已修复

### 缺陷 1：harness.js 模块顶层 `log()` = 导入副作用（决策 B 引入）

- **症状**：任何 `import harness.js` 的工具/测试都会触发一行日志——stdout 喷
  `[logger:harness] …`；若进程注册了退出刷盘，还会把日志写进**当前数据目录**
  （工具跑在真实目录下时就是真实库）。
- **复现**：`NOVELSTUDIO_DATA_DIR` 指向空目录，仅 import 一次即看到输出。
- **修复**：改为 `logTaskHomeDecisionOnce()`——惰性、进程内去重、**首次真正跑任务时**打一次。
  验证：import 完全安静；活实例闸门 10/10 后日志恰好新增一条。

### 缺陷 2：`.p1-baseline/.gitignore` 被 `Add-Content` 写成 UTF-8/GBK 混编

  两次都写成 GBK 字节——git 按字节存储，**已随提交入库**。`read` 工具直接报 invalid UTF-8。
- **修复**：按 HEAD 干净内容重写为无 BOM UTF-8，修正注释并补 `.blind/`。

## 三、反复出现的根因模式（犯错原因，供跨会话注入）

1. **PowerShell 与含中文的文本文件是死对头**（读、写、追加、往返四个方向都栽过）：
   铁律 = 改含中文文件**只用** `edit`/`write` 工具，或
   `[System.IO.File]::WriteAllText(path, text, UTF8Encoding($false))`；
   追加 = 先读全量再整写；**永远不用** `Add-Content`/`Set-Content`/`Get-Content` 做往返。
2. **检查红了必须短路**：`if ($LASTEXITCODE -ne 0) { throw }`——本对话曾因缺这一句把坏文件提交入库。
3. **静态断言断语义，不断代码形状**：断言字面形状会在任何无害重构后报假失败，磨损对红灯的信任。
4. **测试不得依赖环境变量/环境默认值**：策略类参数在测试里显式钉住。
5. **模块导入必须零副作用**：顶层 `log()`/文件写是给"import 一次就查库"这类坑埋雷（缺陷 1）。
6. **新工具引入新产物目录，必须同步 gitignore + 阶段映射**：两个清单漏一个就会在下次运行炸出来。
7. **工具打印的命令必须能被自己的解析器读回来**（含等号/空格两种形式 + 自检）。
8. **"以为在看着、其实没看着"是最贵的错误**：审计/总闸必须显式扫全来源（缺陷 = 决策 B 的审计配套）。
9. 负向断言（"不应当…"）在字段缺失时最容易假通过——先断言存在，再断言取值。
