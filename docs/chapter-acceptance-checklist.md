# 一章一审固定验收清单

> 2026-09-21 定稿。本章清单替代此前散落在对话里的验收口径，作为每一章入库前的一审固定表。
> 2026-10-06 修订：删除「系统出场 5～15 次」「场景 3～5 个」等全局硬配额（避免把经验变成配额、把生成推向工整），篇幅只做诊断，不再按字数自动续写。
> 它与成文提示词里的【本章自检】、直连质检轮 `verifyAIDraft` 与插件侧 `novel_consistency` 共用同一批判据。

## 七项验收

1. **章节边界**：正文只写“本章摘要 + 本章蓝图”覆盖的内容；大纲中标注【未来章·禁止写入】的条目不得被消费。
2. **对手/妖兽阶位**：对手强度与本章摘要一致，不允许无依据升级。
3. **系统人格**：系统按本章剧情需要出场，不设次数配额；每次发言应带来新信息或改变人物处境，纯播报式【】不占多数，单次发言不超过 3 句。
4. **未登记实体**：不得新增未登记的具名角色/地点/妖兽；确需新名字先走提案，作者确认前不入正文。
5. **物件密度**：每章至少一个“可触摸的日常物件”承担情绪。
6. **场面数量**：不设配额，按剧情需要决定（可以只有一个值得展开的场面）；每个出现的场面要有明确地点、出场人物与身体动作，不为凑数硬塞场面。
7. **字数区间**：按作品/章节目标字数把握（第 6 章为 3800～4200 字）；它只是范围参考，不是配额——剧情已完整时短稿可保留，字数不足不再自动在章尾续写。

## 第 6 章对照基线

- 工坊稿（A）：8 个场景 / 7579 字 / 4 处越界 / 1 个未登记实体（赵宇轩）。
- 短稿（B）：3～4 个场景 / 3066 字 / 0 处越界。
- 合成稿目标：场面数量按剧情需要 / 3800～4200 字 / 0 处越界 / 0 个未登记实体。

## 对应机制

- 第 1、4、7 项由成文/蓝图提示词与 `verifyAIDraft` 质检兜底（`public/app.js`）；2026-10-06 起质检为 pass/issues/unknown 三态，unknown 不再冒充通过，篇幅不足也不自动在章尾续写。
- 第 3、5 项来自作品 `style_positive`（写入标准与节奏控制）。
- 第 6 项由“场面数量按剧情需要、篇幅只做诊断”的提示词约束保证（规则真源见 `ai/writing/policy.mjs`）。
- 第 2 项由 `novel_consistency` 的本章自检兜底。
