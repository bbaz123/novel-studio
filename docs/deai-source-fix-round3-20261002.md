## 二、源码改动（按文件）

### `ai/editing/scan.mjs`（确定性扫描）

新增**两类共享正则**（同一口径只准写一份）：

- `PROCESS_EXPLAIN_PATTERNS`：`转/想/念/琢磨/练/捋… + 遍/次 … 顺/熟/能说出口`，以及 `把那句话…顺了/咽回去`
- `NARRATOR_INTRUSION_PATTERNS`：`这个年纪/岁数…遇到这种事`、`换了谁/别人都会…`、`拿正常人作参照`

配套的**逐处定位与整章密度共用同一份口径**：把 `[标签, 正则]` 清单合成**一个** global 正则去扫，
区间天然不重叠（同一句话不会被两条模式各报一次）。打标签用**命名捕获组**而不是"回测匹配片段"
（带回溯引用的模式回测必然失配，实测所有命中都退化成无标签的"机械表达"）。

新增两条**默认关闭**的能力扫描：

- `narrative-distance` → `deterministic:narrator-distance`（逐段定位：过程交代 / 叙述者越界）
- `scene-logic`：
  - `deterministic:object-placement-conflict` —— **零误报**口径：只认"物件名 + 在 + 容器 + 层级"的
    **明确陈述**，且必须是**同一个物件**落在两个不同层级/容器。跨句空间推断（"这一层装着别的东西"）
    **不做**，交给能力文本由模型核对（诚实标注能力边界）。
  - `deterministic:detail-recall` —— 同一编号（`0731` 这类纯数字串）出现在 ≥4 段时报告。

`scanStyleDensity` 新增测量与判据：过渡动作 `gesture-cliche-density`（每千字）+ **`gesture-cliche-repeat`
（同一动作写两遍，作者对本章的意见正是这一种，而全章密度只有 0.2/千字 —— 只报密度会漏）**；
`process-explanation` / `narrator-intrusion`（出现即报，≥2 处时升级为密度表述）。

## 四、过程中被抓出的四个自身缺陷（全部已修，留痕）

1. **`「X 就是 X」式同义复沓` 的旧正则是坏的**（本轮发现的**旧缺陷**）：
   `([^\s，。！？、]{2,8})就是\1` 的首字符类可以只吃一个字，于是"现**在就是**明天早上"（在=在）、
   "也**就是**说"（就=就）全被误报——work#18 第三章实测 3 处**全是误报**。
   改为要求词面 ≥2 字、同词面真重复、允许夹一个逗号，并加否定前瞻排除纯叠字。
2. **判据可能成为"永远不响的死规则"**：`object-placement-conflict` 第一版把动作句"再往里摸"
   读成方位陈述（误报）；第二版对本章静默漏报；第三版才收敛。**每一版都用正例验证过它真的会响**
   —— 只跑负例（"不报"）无法证明一条规则是活的。
3. **层级组永远抓不到**：`(?:里|中|内)?(层级)?` 的顺序会让"夹层里"把"里"吃掉，层级恒为空 →
   规则死。改为"层级词在尾缀前"的两个分支。
4. **字类写错导致整体失配**：物件名写成 `[\u4e00-\u9fa5]{1,8}?`（方括号内其实是否定式）→
   对中文句子整体不匹配。改用 `[^，。！？、\s]{1,8}?`。

另外修掉一处**测试限值过期**（不是本轮引入）：长正文用例的 `request_chars: 1500` 如今连 17 字的
短正文都会被判"必须分段"（审稿提示词自身已 ≈1400 字符），于是 `58ae/58af` 失败。
现在拆成两组设置：分段阈值用例用 1000，单请求归属用例用 8000，两条都通过。

## 五、刻意**没有**做成规则的一条

- **"拧回原来的位置"这类"人物秩序感标签"**：作者自己也说"不是因为前一句不好，而是人物性格已经
  成立了，不需要每个生活动作都再次证明"。把它做成判据必然误报（它本身是有效的写法），
  且会诱导"把生活动作写随意"这种反向修改。**判断权留给人**。

同理，本节所有新增判据都是**描述性**的：报告 + 参考线，不产出"应当改成什么"，
也不进入任何自动改写路径（与 `ai/story-state/style-quality.mjs` 的既有纪律一致）。
