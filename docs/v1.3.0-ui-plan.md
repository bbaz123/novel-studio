### 10.1 真实模型生成修稿补丁（第 2 组）

- 隔离副本再次启动 3798，`/api/ai/chat` 要求模型按“局部补丁”输出两处改写。
- 第 1 次 `max_tokens=3000`：推理再次耗尽 → 空回复（HTTP 200，usage 3270，已留痕）。
- 第 2 次 `max_tokens=8000, reasoning_effort=low`：310 字 JSON，两条 `replace`：
  - I03 锚点 `她显然准备好了更长的安慰` → 改为可观察动作；
  - I04 锚点 `光柱越高，等级越好` → 补充分级例外（颜色/光势）。
- 协议校验：原始回包用 `anchor/revised`（我把提示词写成了旧字段），v2 解码器要求
  `original/replacement + span_id/span`；按 app 生产提示词字段映射并计算真实 span 后，
  `decodePatchOutput(..., {expectedSchemaVersion:2})` → **ok=true, mode=v2, 2 patches**。
- 发现（真实）：模型严格照提示词的字段名输出；生产提示词（`app.js:12636`）用的是
  `issue_ids/span_id/original/replacement`，不能用手写的 `issue_id/anchor` 替代，否则
  补丁虽可解码但 `issue_ids` 为空、无法归属。
- 用量：本组两次 3270 + 3238 tokens；两组共 **4 次调用 / 9825 tokens**，仍低于 ¥2 上限。
- 证据：`artifacts/v130/real-model/revision-response.json`。
