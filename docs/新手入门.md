## 1. 先确认你需要什么

| | 内容 |
| --- | --- |
| ✅ **你需要** | 一台电脑（Windows / macOS / Linux）、**Node.js**（免费，装一次）、一个浏览器（Chrome / Edge / Firefox 等） |
| ✅ **还需要** | 大约 50 MB 磁盘空间（作品多了会再涨） |
| ❌ **不需要** | Git、VS Code、`npm install`、数据库软件、服务器、API Key、网络 |

> 💡 **不需要联网、不需要花钱**：这个工具是「绿色免安装」的本地程序，小说和密钥都只存在你自己电脑上。
> 只有你主动使用 AI 功能时，才会去请求你自己配置的模型服务商（那时才产生费用）。

## 2. 第一步：装 Node.js

Node.js 是这个程序运行需要的「底座」，**只需装一次**。

### Windows

1. 打开 <https://nodejs.org>
2. 点绿色的 **LTS** 版本下载（推荐直接下最新的 **24.x**；**最低要 22.13**，原因见[第 7 节](#7-出错了怎么办按你看到什么查)）
3. 双击下载好的 `.msi`，一路点「Next」→ 最后「Install」，**所有选项保持默认即可**
4. 装完后按 `Win + R`，输入 `cmd`，回车，会弹出一个黑色窗口
5. 在黑窗口里敲下面这行，回车：

```bash
node -v
```

看到类似 `v24.13.0` 的输出，就说明装好了。

> ⚠️ **如果提示「不是内部或外部命令」**：说明刚装完但黑窗口是旧的。**关掉黑窗口重新开一个**再试。

### macOS

到 <https://nodejs.org> 下载 **LTS** 版的 `.pkg`，双击安装，然后打开「终端」敲 `node -v` 验证。

### Linux

用发行版自带的包管理器装 Node 22.13+ 或 24.x，或用 <https://nodejs.org> 的官方二进制包。装完敲 `node -v` 验证。

**验证标准：输出必须是 `v22.13.0` 或更高。** 低于这个版本请重新下载新版覆盖安装。

## 3. 第二步：把项目下载到电脑

### 方式 A：下载 ZIP（推荐给新手）

1. 打开项目仓库页面 <https://github.com/bbaz123/novel-studio>
2. 点绿色的 **`Code`** 按钮 → 在弹出菜单里选 **`Download ZIP`**
3. 下载完成后，右键压缩包 → **解压到**一个你找得到的位置

> ⚠️ **解压路径建议**：不要放在含**中文**或**空格**的路径里，也不要放在 OneDrive / iCloud 这类**自动同步**的目录里（同步会干扰数据库文件）。
> 推荐类似 `D:\novel-studio`、`C:\novel-studio` 这样的路径。

### 方式 B：会用 Git 的话

```bash
git clone https://github.com/bbaz123/novel-studio.git
```

> 📌 注意：下载下来的目录名可能是 `novel-studio-main`（ZIP 方式），这不影响使用。

## 4. 第三步：启动

### Windows

进入项目文件夹，**双击 `start-novel-studio.cmd`**。

它会自动做这几件事：

1. 检查有没有装 Node.js、版本够不够（不够会提示你，窗口会停住让你看清楚）
2. 如果服务已经在运行 → 直接帮你打开浏览器（**不会重复启动**，所以双击多次也没关系）
3. 否则弹出一个标题为 **「Novel Studio Server」** 的黑色窗口来运行服务
4. 等它准备好后，自动用默认浏览器打开界面

### macOS / Linux

在项目目录里执行：

```bash
npm start
```

然后手动打开浏览器访问 <http://localhost:3737>。

### 4.1 怎么算启动成功

任务栏里出现一个黑色窗口，里面有类似这两行（中间可能还有一行自检日志，属正常）：

```text
[logger:server] Novel Studio 服务启动
Novel Studio is running at http://localhost:3737
```

同时浏览器自动打开，页面左上角显示 **「📚 我的作品」**。

如果浏览器没自动打开，**手动**在地址栏输入：

```text
http://localhost:3737
```

### 4.2 想停止服务

推荐在服务窗口里按 **`Ctrl + C`**——它会先把手头的数据落盘再退出，最稳妥。
也可以直接关掉那个黑色窗口。

> 关掉服务不影响你的作品，数据都已经存在硬盘上了。下次照常双击启动即可。

### 4.3 每次写作怎么开始

**双击 `start-novel-studio.cmd` → 浏览器自动打开 → 开写。** 就这一步。

### 4.4 想换个端口（默认 3737 被占用时）

```powershell
# Windows PowerShell
$env:PORT=3738; npm start
```

```bash
# macOS / Linux
PORT=3738 npm start
```

然后访问 <http://localhost:3738>。

> `start-novel-studio.cmd` 是写死 3737 的。如果你固定要换端口，就在 PowerShell 里用上面的命令启动，不要用 `.cmd`。

### 4.5 想让桌面有个图标（可选，仅 Windows）

```powershell
powershell -ExecutionPolicy Bypass -File .\create-desktop-shortcut.ps1
```

会在桌面生成一个「小说工坊」快捷方式，双击它等于双击 `start-novel-studio.cmd`。

> 💡 示例小说随时可以删：「我的作品」页的「🧪 示例小说」区块 → 「删除示例数据」。你自己的作品不受影响。

打开后是一屏三栏：

| **中间正文编辑器** | 左侧章节树选章，右侧写正文：富文本排版（加粗/标题/引用/列表）、自动保存、实时字数统计，工具栏还有 `✍️ AI 写作` |

界面里凡是标题旁边有**小问号 `?`** 的地方（例如「小说设定」页的说明、「SillyTavern 设置」标题、「章节作者注」卡片），

侧栏每个入口、正文工具栏的 `✍️ AI 写作` / `✨ 润色` / `📖 扩写`、参考面板的 `伏笔` / `红线` / `上下文` 页签，
鼠标悬停也会给出说明。**不用为了搞懂一个词去翻文档。**

## 6. 手动写作的日常流程

不接 AI 也能完整写完一本小说，推荐这样组织：

1. **新建作品** → 填书名、简介
2. **建卷**（可选但推荐，例：第一卷 · 雾都）
3. **建章节**，每章写正文；写完一章就用章节树切到下一章
4. **随手记设定**：`小说设定 → 设定库` 建世界观词条，`→ 角色` 建角色卡，`→ 大纲` 写卷纲和章纲
5. **在正文里关联词条**：选中正文中的名词 → 关联到设定词条，之后鼠标悬停就能看到解释
6. **每章写完，记一条长期记忆**：`小说设定 → 长期记忆` 记录「这一章发生了什么」（谁死了、伏笔埋了什么），写后面章节时自己回看很方便
7. **善用全局搜索**：顶栏中间的搜索框能同时搜设定词条、大纲、章节正文和角色
8. **怕写坏就存历史版本**：正文工具栏支持手动保存历史版本，可以随时查看和恢复

> 💾 **自动保存**：正文编辑是自动保存的，不需要按 `Ctrl + S`。但服务没关就强制关机、或直接删 `data` 目录，仍可能丢数据——正常使用不必担心。

## 7. 出错了怎么办（按「你看到什么」查）

### 7.1 双击没反应 / 窗口一闪而过 / 提示 Node.js

| 你看到的 | 原因 | 怎么办 |
| --- | --- | --- |
| 提示 `Node.js not found. Please install Node.js 22+ first` | 没装 Node.js，或装了但没重启命令行 | 装 Node.js（[第 2 节](#2-第一步装-nodejs)）后重试；刚装完请**重开**一个命令行窗口 |
| 提示 `Node.js 22+ is required. Current version: v20.x.x` | Node.js 版本太旧 | 到 <https://nodejs.org> 下载 LTS 版覆盖安装 |
| 双击后什么都不弹 | 文件被解压工具「套了一层目录」，或 `.cmd` 被安全软件拦了 | 确认 `start-novel-studio.cmd` 和 `server.js` 在**同一个目录**下；必要时右键 `.cmd` → 以管理员身份运行 |

### 7.2 浏览器打开是「无法访问此网站」

1. **先等 5 秒再刷新**——服务启动需要一点时间
2. 看那个黑色服务窗口里有没有报错（对照 7.3）
3. 手动访问 <http://localhost:3737> 再试一次
4. 还是不行：关掉服务窗口，重新双击 `start-novel-studio.cmd`

### 7.3 黑窗口里的报错信息（重点看这里）

**① 端口被占用**

```text
[logger:process] 未捕获异常：listen EADDRINUSE: address already in use 127.0.0.1:3737
```

意思：**3737 端口被别的程序占用了**，服务起不来并已退出。

怎么办（三选一）：

- 换端口启动：`$env:PORT=3738; npm start`（PowerShell）/ `PORT=3738 npm start`（macOS、Linux）
- 查是谁占用了：

  ```powershell
  netstat -ano | findstr 3737
  ```

  记下最后一列的数字（进程 PID），到「任务管理器 → 详细信息」里按 PID 找到那个程序并结束它
- 确认是不是**你自己已经开着一个**了：如果已经有一个服务在跑，直接用浏览器访问 <http://localhost:3737> 就行，不用再启动一次

**② 提示 `node:sqlite` 相关错误**

```text
Error [ERR_UNKNOWN_BUILTIN_MODULE]: No such built-in module: node:sqlite
```

（报错原文会随 Node.js 小版本略有差异，也可能提示需要 `--experimental-sqlite` 参数——只要出现 `node:sqlite` 或 `sqlite` 字样，就是下面这个问题。）

意思：**你的 Node.js 版本偏低**。`node:sqlite` 是 Node.js 22.5 才加入的内置模块，但在 **22.13 之前它默认是关闭的**，必须额外加启动参数才能用；本项目用的是普通启动方式，所以：

> ✅ **实际版本门槛是 Node.js 22.13 或更高**（官方版本说明：v22.13.0 起 `node:sqlite` 不再需要 `--experimental-sqlite`）。

请升级到 **22.13+（推荐 24 LTS）** 后重试。

**③ 报错里出现 `EACCES` / 权限相关字样**

可能把项目放在了需要管理员权限的目录（如 `C:\Program Files`）。把整个项目文件夹移到 `D:\`、桌面等普通目录再试。

### 7.4 服务在跑，但就是打不开 / 卡

- 强制刷新页面：`Ctrl + F5`
- 换个浏览器试试（推荐 Edge / Chrome）
- 到侧栏「🧾 日志」页看看有没有红色错误记录；把这个页面截图，问题更容易被定位

### 7.5 能在手机或另一台电脑上打开吗？

**默认不能。** 服务只监听本机地址 `127.0.0.1`，局域网里的其它设备访问不到（这是出于安全考虑：作品和 API Key 都在本机数据库里）。

确实需要局域网访问，得自行修改 `server.js` 里的监听地址——这属于进阶改动，不在本文范围。

### 7.6 AI 功能报错了（界面里能自己看的部分）

| 你看到的 | 意思 | 怎么办 |
| --- | --- | --- |
| 「未找到 deepseek-harness（…）。已检查：…」 | 工坊不知道 dsh 装在哪——报错里会列出**它按顺序找过的每个位置** | 去 `⚙️ AI 设置 → 🛠 本地创作内核（dsh）` 填仓库路径并保存；旁边的「📦 工具与环境清单」也会显示它到底找没找到 |
| 「这个目录不像 dsh 仓库」 | 填的目录不是 dsh 源码仓库（例如填成了工坊自己的目录） | 确认路径指向的是 `deepseek-harness` 仓库根目录（里面有 `apps/` 或 `packages/`） |
| OpenViking 显示「服务未响应」 | 记忆库服务没启动，或地址/端口不对 | 先用「测试连接」重试；确认 OpenViking 已启动。**这不影响手动写作**，AI 写作只是少一层语义召回 |
| 卡片上写着「已保存」但 AI 还是用旧配置 | 环境变量优先级高于界面里填的值 | 看卡片上「来源」那一行：若显示"环境变量"，说明是环境变量说了算（脚本化/多实例场景常见），要么改环境变量，要么去掉它 |
| 想确认到底缺什么 | — | `⚙️ AI 设置 → 📦 工具与环境清单`：四类工具逐项显示「装没装 + 不装会少什么 + 去哪儿装」 |
| 页面提示「**服务端仍在运行旧代码**」，或卡片显示「检测失败：API not found」 | 你更新了程序文件，但**服务进程还是更新前启动的那个**——新接口在旧进程里不存在 | 按提示重启：关掉那个黑色服务窗口（或在窗口里按 `Ctrl + C`）→ 重新双击 `start-novel-studio.cmd` → 回到浏览器按 `Ctrl + F5` 刷新。**作品数据不受影响**（已保存在 `data/`） |

## 8. 你的数据：在哪、怎么备份、怎么搬家

| | 位置 / 做法 |
| --- | --- |
| **全部数据** | 项目目录下的 **`data/`** 文件夹 |
| **作品数据库** | `data/novel.db`（包含所有作品、设定、正文，**以及你的 API Key**） |
| **运行日志** | `data/logs/`（保留 14 天，自动清理） |
| **运行追踪录制** | `data/debug/`（保留最近 20 个会话，可在界面里清空） |
| **同步队列** | `data/openviking-pending.jsonl`（没接 OpenViking 时基本为空） |

### 8.1 怎么备份（重要）

> ⚠️ **备份请「先关掉服务，再复制整个 `data` 文件夹」。**
>
> 不要只复制 `novel.db` 一个文件：数据库启用了 **WAL 模式**，最近的写入可能还在旁边的
> `novel.db-wal` 里。只拷主文件有可能丢掉最近几章的改动。

正确做法：

1. 在服务窗口按 `Ctrl + C` 停止服务
2. 把整个 **`data/`** 文件夹复制到 U 盘 / 网盘 / 另一个盘
3. 这就是一份完整备份

### 8.2 怎么恢复到另一台电脑

1. 在新电脑上按本文装好 Node.js 和项目
2. **先启动一次再关掉**（让它生成 `data/` 目录结构），或者直接手动创建
3. 用备份的 **`data/`** 文件夹覆盖新电脑上的 `data/` 文件夹
4. 重新启动，作品就回来了

### 8.3 隐私提醒

`data/novel.db` 里**同时存着你的作品正文和 API Key**：

- ❌ 不要把这个文件（或 `data/` 文件夹）发给别人、上传到网盘公开链接、提交进 Git 仓库
- ✅ 项目自带的 `.gitignore` 已经排除了 `data/`，正常提交代码不会带上它

## 9. 想用 AI 写作：最小配置

不做这一步，前面所有手动写作功能都照常可用。想做，看下面。

### 9.1 先明确：AI 功能要花你自己的钱

AI 功能会请求**你自己配置的模型服务商**，按用量计费。本项目不代收费用、也不包含任何额度。

### 9.2 第一步：在界面里填 API 配置

在**初始页**（没进入作品时）点左侧「**✨ AI 创作**」→「**⚙️ AI 设置**」；
（进入作品后也可以从「**AI创造板块 → AI 设置**」进入）

新建一个配置，填：

| 字段 | 填什么 |
| --- | --- |
| 配置名称 | 随便起，例如 `deepseek` |
| Base URL | DeepSeek 官方填 `https://api.deepseek.com`（其它 OpenAI 兼容服务商填它自己的地址） |
| API Key | 到你的模型服务商控制台申请（DeepSeek 在 <https://platform.deepseek.com> 的「API keys」页面创建）。**只保存在你本机数据库里** |
| 模型 | 下拉里选 `deepseek-flash`（V4.1 Flash，默认也是唯一推荐项）即可 |

填完点「**测试连接**」，成功就说明通了。

> ℹ️ 模型下拉里填的 `model` 只对少数功能生效：**正文写作、审稿、修稿、设定生成等关键环节的模型是由程序内置策略决定的**（见 README「🤖 AI 功能配置」），所以改这里的模型名不会影响那些环节。这些环节现在统一用 V4.1 Flash，需要"多想一会儿"的环节（审稿/修稿/设定成文）由思考强度自动调高——你不用手改任何东西。

### 9.3 第二步：把「记忆库」和「创作内核」接上（都在界面里，不用命令行）

`⚙️ AI 设置` 页往下拉，有三张卡。**只填 API 也能用最基本的 AI 功能；下面这些是让 AI 更聪明 / 用上深度创作的可选项。**

| 卡片 | 它管什么 | 你要做什么 |
| --- | --- | --- |
| 🧠 **OpenViking 记忆库** | 让 AI 能「记得」很久以前写过的设定与情节（语义召回）。**不装完全不影响写作**，只是少一层记忆 | 装好 OpenViking 后，把它的**服务地址**（默认 `http://127.0.0.1:1933`）和**访问令牌**填进来 →「测试连接」→「保存并生效」。卡上会显示这份凭证当前是从哪来的 |
| 🛠 **本地创作内核（dsh）** | `✍️ AI 写作` / 创作工作台 / AI 自动创建小说 的**运行内核**。不装则这些功能用不了，手动写作照常 | 装好 DeepSeek Harness（dsh）后，把**仓库路径**填进来 →「保存路径」。卡上会告诉你它在不在、是否构建过、按顺序找过哪几个位置 |
| 📦 **工具与环境清单** | 一张总表：Node.js / dsh / 创作插件 / OpenViking **各是干什么的、你现在装没装、不装会少什么功能、去哪儿装** | 看一眼就知道自己缺什么；每行都能一键复制安装命令 |

> ✅ **填了就生效，不用重启服务**：这些值保存在本机数据库里，下次启动仍然有效。
>
> 🔁 想让 dsh 那边（GUI 会话 / AI 写作任务）也用上同一个记忆库？点 OpenViking 卡上的
> **「写入全局配置（让 dsh 也用）」**——它会先把 `~/.openviking/ovcli.conf` **备份**一份，只改地址与令牌两个字段，其它内容原样保留，并告诉你还原方法。
>
> 🧩 创作插件（novel-writing）的安装命令也在清单里，复制粘贴执行一次即可。

### 9.4 第三步：分清「直连」和「慢通道」

| 通道 | 干什么 | 需要什么 |
| --- | --- | --- |
| **直连通道**（秒级） | 润色、扩写、细纲、性格校对这类单轮短任务 | 只要 9.2 配好 API 就行 |
| **慢通道**（走创作内核） | `✍️ AI 写作`、AI 续写、AI 自动创建小说、AI 生成设定/大纲/角色卡等 | 除了 API，**还需要额外安装 DeepSeek Harness（dsh）与创作插件** |

如果只配了 API Key，慢通道的功能**可能不可用**。装 dsh 和插件的完整步骤见 README 的「🚀 安装与运行（详细步骤）→ 第 5 步」；
但**告诉工坊 dsh 装在哪**这一步不必碰命令行——直接在 `⚙️ AI 设置 → 🛠 本地创作内核（dsh）` 里填路径保存即可（见上一节）。

### 9.5 用 AI 时的几个安全习惯

- **AI 写作会先弹「需求确认框」**，确认后才发起付费调用，避免误触扣费
- AI 生成的事件 / 记忆**先落「提案」**，不会直接写进账本；你在弹窗里勾选采纳才入账
- 觉得 AI 跑偏：从正文工具栏的**历史版本**里恢复（AI 成稿写回章节时，旧稿会自动存为一个历史版本，可随时查看与恢复）
- 不想用 AI 了：在 AI 设置里删掉配置即可（或保留配置不用）

## 10. 卸载 / 换电脑

| 想做的事 | 怎么做 |
| --- | --- |
| **彻底卸载** | 直接删掉整个项目文件夹即可。程序是绿色免安装的，不写注册表、不留后台服务 |
| **换电脑继续写** | 见 [8.2](#82-怎么恢复到另一台电脑)：带走 `data/` 文件夹 |
| **只清理日志/录制** | 删 `data/logs/` 和 `data/debug/`（不影响作品）；也可在界面「🧾 日志」页和「🐞 运行追踪」页里一键清空 |
| **想重新开始** | 关掉服务，删掉 `data/novel.db*`（**`-wal`、`-shm` 一起删**），重启后会自动建一个空库。⚠️ 这会丢失全部作品，务必先备份 |

## 11. 名词小词典（看不懂的术语都在这）

| 名词 | 大白话 |
| --- | --- |
| **作品 / 卷 / 章节 / 场景** | 一本书 → 分成几卷 → 每卷若干章 → 一章里可再分场景 |
| **设定库** | 你的世界观词条（地名、门派、道具、术语…），可在正文里关联和悬停预览 |
| **世界观词条 vs 设定库词条** | 两套独立数据：`小说设定 → 设定库` 是给正文关联用的；`AI创造板块 → SillyTavern 设置` 里的世界观词条是专门喂给 AI 的（按优先级/是否激活控制）。AI 设置页能看到这个区别 |
| **角色卡** | 人物的档案：外貌、性格、背景、当前状态、人物关系、说话口吻示例 |
| **剧情线 / 大纲** | **同一批章节的两种看法，不是两套数据**：剧情线 = 按「线索」横着看（这条线走到哪了，主线一条、支线若干）；大纲 = 按「卷 / 章」竖着看（整本书的结构长什么样，思维导图）。同一章可以既属于某条剧情线、又挂在某个卷下，改一边不会丢另一边 |
| **长期记忆（故事摘要）** | 「已经发生过什么」——重要剧情、伏笔、角色状态变化；AI 写作时会参考。**它是提炼后的摘要** |
| **事件账本 / 伏笔** | 按时间记录的事件流水（谁在哪一章做了什么）；伏笔是其中的特殊事件，可标记「已埋下 / 已回收」，防止烂尾忘收。**它是明细**——与长期记忆的关系是「流水 vs 摘要」 |
| **作品作者注 / 章节作者注** | 给 AI 的写作指示。作品作者注 = 整本书通用（如「全程第一人称」）；章节作者注 = 只对某一章生效（如「这章节奏要快」）。都在「SillyTavern 设置」或「长期记忆」页里，**不写也完全不影响使用** |
| **章节蓝图** | AI 动笔前先跟你确认的一份「本章要写什么」的计划（场景目标 / 情节点 / 冲突 / 角色变化 / 钩子 / 要回扣的设定）。确认后才按它成文，避免一次性跑偏整章 |
| **红线** | 你设定的禁用表达（反 AI 腔规则），AI 成文后会按它扫描一遍 |
| **上下文** | AI 每次动笔前「看到的全部资料」；本工具会按用途分层装配，省 token 又不丢关键信息 |
| **直连通道** | 直接调用模型 API，秒级响应，适合润色/扩写这类短任务 |
| **慢通道 / Harness** | 通过 DeepSeek Harness（dsh）跑的多阶段创作任务，较慢但更完整 |
| **DeepSeek Harness（dsh）** | 驱动「AI 创作内核」的程序，**可选**；不装也能手动写作。装在哪个目录可以在 `AI 设置 → 本地创作内核` 里填 |
| **SillyTavern** | 另一个开源 AI 聊天/角色扮演前端；本项目**借鉴了它的一套做法**（角色卡的人设与对话示例、世界观词条当成素材喂给模型）。工坊里的「SillyTavern 设置」页就是这些素材的编辑处，与 SillyTavern 本体无关，不需要安装它 |
| **profile** | dsh 的配置档（可以理解为「给不同任务用的不同运行环境」） |
| **OpenViking** | 一个可选的本地记忆库，让 AI 能「语义召回」很久以前的设定。**不装完全不影响使用**；地址/令牌可在 `AI 设置 → OpenViking 记忆库` 里填 |
| **运行追踪 / 日志** | 排查问题和看性能用的记录，正常写作可以无视 |
