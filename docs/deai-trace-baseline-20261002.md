# 结构型 AI 痕迹 · 基线与检测口径（2026-10-02）

## 为什么有这份文件

第三章（chapter_id 121）对既有 **28 条写作红线**与 **7 项编辑能力**的确定性扫描是 **0 命中**，
但短句、精确动作链与意象回收这三类痕迹在文本里肉眼可见。结论是：那类痕迹不是"词"，是**密度**；
词表型规则天生测不到"用得太整齐"。本文件记录新增的 `style-density`（结构密度审视）能力的
**口径、阈值与初始基线**，作为以后"改前 / 改后"的唯一判据来源。

## 能力定位（重要）

- 能力 id：`style-density`，目录名「结构密度审视」，`tasks: ['review']`。
- **只报告，不约束生成**：write 任务下 `abilityDecision` 返回 `task_not_applicable(write)`，
  这条能力的规则文本不会进入任何生成请求的规则块；它只在扫描端点
  （`POST /api/novel/editing/scan`，`task='review'`）里产出 finding 与测量值。
- 默认**关闭**：作者在「创作上下文 → 编辑规则」里显式勾选后才参与扫描。
- 不返回"应当改成什么"，也不驱动任何自动改写（与 `ai/story-state/style-quality.mjs` 的
  "指标是描述性的，不是规范性的"同一条纪律）。

## 判据与阈值（`ai/editing/scan.mjs` 的 `DENSITY` 常量）

- 短句占比：句长 ≤6 字符（含句末标点，与 `style-quality.mjs` 的句长口径一致）；参考线 25%，33% 以上记为 medium。
- 同构句式：`不是X。是Y。`、`X 就是 X`、`没有A。也没有B。`、连续三个 ≤4 字短句；同一家族出现 ≥2 次即报。
- 意象复现：2–5 字中文 n-gram，须出现 ≥4 次且跨 ≥3 段；排除功能字开头/结尾与动词收尾的碎片；
  同一词面被更长候选包含时让位。参考线写作"单个 ≤3 次"。
- 微操作链：`拧/按/对准/折/搓/塞` 等微操作动词每千字次数（参考线 9），以及同段连续 ≥4 个 ≤12 字短动作句。

## 已知局限（不要当成精确结论）

1. n-gram 仍会切出跨词碎片（如"句话"来自"一句话"）；榜单是**线索**，不是词表结论。
2. 短句占比口径**含句末标点**，因此与"按标点切分后再数字数"的自制脚本会差几个百分点，比较时须同口径。
3. 三章基线全部来自 AI 生成的正文，**尚无人写基线**；参考线取自这三章的实测值，属于暂定值。
   作者可以调 `DENSITY` 常量，或以后用 R09 作者样文（`author_samples`/`style_profiles`）建立人写基线。
4. `action_runs`（同段连续短动作句）在三章都是 0：目前靠"微操作动词密度"抓细节链，段落级判据偏保守。

## 复现方式

`node --input-type=module -e` 里 import `ai/editing/scan.mjs` 的 `scanEditing`，
传入正文与 `{ abilities: ['style-density'], genre: 'urban', task: 'review', characters }`，
读取返回值里的 `scanned.density` 与 `findings`。界面侧：勾选该能力后点确定性检查
（`public/app.js` 的扫描面板会按 `rule_id / 位置 / 摘录 / 建议` 列出）。
