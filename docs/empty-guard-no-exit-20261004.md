# 空稿护栏的"出路按钮"从来没被画出来（2026-10-04）

## 报障原文

> 编辑器当前是空的，已暂停自动保存（正文没有被覆盖）——用编辑器上方的恢复条取回原稿，
> 或明确选择清空本章，**你没有按钮让我选择清空本章，一刷新又恢复了**

## 现象拆成两半

1. **那句话把作者指向了一个不存在的出口**：提示说"用恢复条取回原稿，或明确选择清空本章"，
   而恢复条上既没有 `取回历史版本`，也没有 `确认清空本章`。
2. **于是清空这一章做不到**：刷新之后正文又回来了（护栏没让空稿落盘——这一步本身是对的），
   作者被困在"想清空 → 被拦 → 没有按钮 → 刷新复原"的循环里。

先确认数据：**没有被清空的章节**。ch119 4854B / ch120 4705B / ch121 5631B 都在；
ch122-124 是导入时留下的 11 字节占位（`<p><br></p>` 一类），ch125+ 本来就是空的。
护栏拦住了写入，这也是它该做的。

## 根因（可执行）

空内容护栏命中后走的三条路，都只调了一个名字很像是"刷新恢复条"的函数：

| 路径 | 位置 | 做了什么 |
| --- | --- | --- |
| 自动保存闸门（800ms） | `public/app.js` `scheduleSave()` | 记状态 + 状态栏 + toast + `refreshChapterRecovery` |
| 服务端拦下空正文 | `tripEmptyGuardState()` | 同上 |
| 其它保存失败 | `handleChapterWriteError()` | 同上 |

而 **`refreshChapterRecovery()` 只取数据、不碰 DOM** —— 真正把 HTML 写进恢复条的那句
写在 `render()` 的 `.then()` 里（还有模板 `renderWriting` 里渲染时那一份）。
所以"调了它就等于按钮会出现"这个假设从一开始就是错的。

更糟的是，自动保存那条路还多了一层闸门：

```js
if (snap.id && state.recoveryForChapter !== snap.id) refreshChapterRecovery(snap.id)…
```

`state.recoveryForChapter` 在**打开章节时就被设成该章**（`render()` 拉过一次），
于是这个条件恒为 false —— **连那次只取数据的调用都被整个跳过**。
恢复条于是保持打开章节时的旧 HTML，按钮永远不出现。

这不是新缺陷：上一轮（2026-10-02）修"作者看到'已暂停'却没有出路"时，
代码里甚至留下了注释"必须刷新恢复条：两条出路都在那里"——**意图写下来了，
但没有任何东西验证这个意图**，而它调用的函数并不做那件事。

## 修法

1. `refreshRecoveryBar(chapterId)`：接受显式章号；不传时按 **当前章 → 编辑器 dataset** 取。
   顺序不能倒：编辑器节点在切章的一瞬间可能还挂着上一章的 dataset。
2. `refreshChapterRecovery()` 末尾补一次 `refreshRecoveryBar(id)`：
   **取数据与画界面合成一件事**，任何"刷新数据"的调用点自然也就刷新了界面。
   （切章早退那条分支不画——那时要画的是别的章。）
3. 三个调用点各补一次**同步**绘制（不等网络）：闸门用 `snap.id`、`tripEmptyGuardState`
   与保存失败分支用 `id`。通行原则是：**"已暂停"这句话与它的出路必须同时出现**。

## 验证

先写回归、确认它**红**，再修：

- 修前：`P-EMPTY-11` → `FAIL … {"blocked":true,"bar":""}`（护栏确实拦下了，恢复条确实是空的）
  —— 与作者描述逐字吻合；`P-EMPTY-12` 同样红。
- 修后：两条都 PASS；全套 `node frontend-test.mjs` → **397 PASS / 0 FAIL**。
- 服务端 `app.js` 与磁盘逐字节一致 → 刷新页面即生效（**本次不需要重启服务**：纯前端）。

回归的复现条件写得很明确：`state.recoveryForChapter === 121`（该章数据已取过）
+ 编辑器为空 + 本页见过该章正文（峰值 3982）。少任何一条都复现不出来。

## 顺带修掉的同类隐患

`refreshRecoveryBar` 被我自己在同一天的"关闭生成稿/结果/审稿"三处用到（就地重画）。
它此前按 `state.currentChapterId` 取章，我在这一轮一度改成"编辑器 dataset 优先"，
结果两条既有回归当场变红（`P-DISMISS-5`、`P-DISMISS-8`：恢复条不再重画）——
**说明改一个共享辅助函数的取数顺序，等于改了所有调用方的行为**。
最终顺序按生产语义定：当前章优先，dataset 只作兜底。
