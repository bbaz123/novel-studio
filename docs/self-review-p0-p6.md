### 新发现 F5 · 埋点表的孤儿行（未修，已进决策页 D6）

`ai_eval_events` 的 `work_id` / `chapter_id` 是**裸 INTEGER**，没有像其它二十余张作品域表那样

**为什么没直接修**：删作品是否该连带删埋点，是**语义选择**（保留长期分析历史 vs 与其它表一致），

### 新发现 F10 · 「可独立回滚」那一列是我手写的判断，**八条里错了四条**（**已改为推导**）

`docs/phase-map.md` 的「回滚」列原先是**我写的判断**，核对器只检查了格式合法
（是不是 `independent`/`shared` 之一），**没检查它是不是真的**。实测：

- `ai/context/layers.mjs` 是 P1 的文件，却被装配器（P2）与 `server.js` import
  → 单独撤掉 P1 会**当场打断 P2**。P1 却被我标成"可独立回滚"。
- 同类错误还有 P3、P6、X 三处。
- 更深一层：我的「改动面」清单**本身漏记**（`public/app.js` 明明被 P4/P5 改过、
  `server.js` 被 P3 改过，都没列进去）——漏记会让回滚判定**偏乐观**。

现已改为**从真实 `import` 图推导**，三档：`independent` / `tool-only`（只被验收工具 import）
/ `shared`（与别阶段同文件，或被生产代码 import），并要求数据里的声明与推导一致，
不一致就核对失败。**推导结论：没有任何阶段可独立回滚**，只有 X 是 `tool-only`。
这条直接改写了 D1 的理由——**提交点是唯一的回退粒度**。

阴性对照：把 P1 硬声明成 `independent` → 核对报
`✗ P1 推导=shared　声明=independent ← 声明与推导不一致`。

### 新发现 F9 · 语法检查清单是手写枚举，于是漏检了自己新加的模块（**已修**）

套件的语法检查原本**手写枚举**要检查的文件（50 个）。后果：`ai/harness-env.mjs` 与
`ai/edit-distance.mjs` 加进仓库后**一直没被检查过**——而它们正是我这两轮新写的模块。
与"阶段映射"要解决的是同一个病：**清单必须从被检查的对象派生**。

改成走目录派生（实际 65 个），并**自带护栏**：钉一份代表性文件清单，缺任何一个即判失败——
因为"派生"一旦把排除规则写宽，就会静默漏掉源码而仍然报绿。

阴性对照两条：
1. 把**此前漏检**的 `ai/edit-distance.mjs` 写坏 → 语法项报 `语法失败: ai/edit-distance.mjs`；
2. 把排除规则写宽成 `ai` → 护栏报 `漏掉 ai/policy.mjs, ai/context/layers.mjs, …`。

### 新发现 F7 · 「断言助手签名写错」导致一条断言恒判通过（**已修**）

给 P0 补线路层验证时，我把断言助手写成 `ok(名称, 详情)`，而调用处按 `ok(名称, 条件, 详情)`
传三参 —— 于是**条件根本没被求值、恒判通过**。线索是输出里一个突兀的 `true`：
详情位置被塞进了布尔值。

**为什么这条值得单独记**：它比"检查没命中"更危险——**检查报绿、但什么都没查**。
与第二轮自审里"变异测试本身没改到东西"是同一类病：**验证装置自己没被验证**。

两条应对都已落地：
1. 助手改为 `check(名称, 条件, 详情)`，与其余工具统一；
2. 工具里加一条**断言助手自检**（喂一个假条件，确认它会被计入失败），
   跑起来会打印「✓ 断言助手自检：假条件会被计入失败」。

### 新发现 F6 · 压缩提示会被自己截掉（**已修并验证**）

`mergeMemoryDraft` 只拼接不压缩 → 长期记忆随章节无界增长；而装配器对每层是按 cap
**从头部**截断。压缩提示原先拼在正文**末尾**，于是**记忆越长，提示越会被自己截掉**——
恰恰在最该提示压缩的时候提示消失。实测 `work#16`：记忆 9000 字 / cap 2200 → 层内只剩截断提示。

修法：提示挪到正文开头。代价如实量化：层窗口让出 **63 字 / 2200 = 2.9%**（总长不变），
被挤掉的部分仍可经 `novel_memory_read` 查回。

**影响面逐字实测**：压力 50 个用例中 35 个逐字未变、15 个（全部 w16）恰好是
「窗口让出 63 字、其余逐字相同」、0 异常；**真实作品 20/20 逐字节未变**。

固化为 `verify-memory-hint.mjs`；阴性对照用**修复前的真实基线**（失败 3/3），无需造变异。

## 六、这次自审的方法论收获

1. **"我没碰它" 必须靠工具验证，不能靠叙述**。F1 就是这么被发现的：不是我觉得没写，
   而是去查了 mtime 和逐表对比。反过来，我一开始怀疑的「真实库被大改」也被同一套对比否证了。
2. **既有失败要用对照实验摘清**。L13 若只靠推断，「大概率是环境问题」和「确实是我改坏的」
   在报告里长得一模一样。取一份 HEAD 快照跑同一套件，成本很低，结论是确定的。
3. **校验器要从被校验对象派生，不要重复实现**。P5 已经吃过两次（提示语样本过期 → 误报 45 处；
   手写正则归一化静默失效）。F3 是同一个病的另一面：**文档里的行号就是一种重复实现**。
