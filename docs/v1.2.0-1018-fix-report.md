## 1. 每项修复与证据

### P01 伏笔状态与审批非原子 → 已修复

- `server.js` 的 `POST /api/novel/foreshadows/:id/status`：
  ① 所有只读校验（状态枚举、`resolves_event_id` 存在/同作品/非自身/正整数）**先于**任何写入；
  ② 审批改为"事务外预检（`consume:false`）+ 事务内消费"；
  ③ 状态更新带**当前值条件**（并发冲突返回 409，值未变的重复提交按幂等处理）；
  ④ 状态、回收关联、审批消费在同一个 `withTx` 里。
- 附带修复：`/api/novel/approvals` 创建 `foreshadow_status` 审批时**从未写入绑定**
  （`checkBinding` 永远拿到空 `event_id`），导致该授权链实际不可用。现在绑定由服务端从真实存储计算。
- 证据：`.p1-baseline/test-1018-foreshadow-atomic.mjs`（20 条断言：无效/跨作品目标零副作用、
  审批失败不被吃掉、并发同一审批只成功一次）。

### P02 记忆回滚缺少作者边界与归属校验 → 已修复

- `POST /api/story_memory/rollback`：作者通道限定（模型 403）；`version_id` 严格正整数；
  版本归属与回滚写在同一事务；声明 `work_id` 时校验归属；不存在返回 404。
- 证据：`test-1018-auth-and-memory.mjs`（模型 403、非法 id 400/404、跨作品 400、合法 200）。

### P03 作者决策路由权限矩阵 → 已修复

新增 `AUTHOR_ONLY_WRITES` 表并在**路由分派前**统一判定（模型通道一律 403）：
红线 PUT、连续性豁免 POST、连续性阈值 POST、旧提案 reject、状态提案 reject、
章节蓝图 PUT、蓝图 DELETE、审稿 dismiss、审稿 checklist、生成稿 dismiss、记忆回滚。

- 证据：`test-1018-auth-and-memory.mjs` 10 条模型通道用例全部 403 且库无变化；作者通道 4 项仍 200。

### P04 Origin/Host 精确校验 → 已修复

- 新增 `ai/http/origin.mjs`：写请求按**协议 + 主机 + 端口**完整比较 Origin；
  Host 必须存在、为本机名、端口等于实际监听端口；缺失 Host 不再视为可信。
- 仍允许无 Origin 的 CLI/插件（它们的身份由随机能力令牌裁决），但目标主机与端口必须精确匹配。
- 证据：`test-1018-http-entry.mjs`（同机 5173 端口 403；异主机/端口不符/缺 Host 403；同端口 201）。

### P05 JSON 解析失败仍执行副作用 → 已修复

- 5 处 `readBody(req).catch(() => ({}))` 全部改为 `readBodyOrError(req, res)`：
  畸形 JSON → 400、超限 → 413，并且**立即返回**（不再执行备份、蓝图删除、追踪启动、任务标记）。
- 证据同上（畸形 JSON 时备份文件数/蓝图数不变、追踪未启动；合法请求仍 201/200）。

### P06 Windows 启动脚本 → 已修复

- 端口读 `PORT`（默认 3737）并校验 1–65535；URL 用 `127.0.0.1:PORT`；
  就绪判据改为 `curl --fail /api/readiness`；端口被占与"服务未就绪"分开提示；
  超时返回非零且**不打开浏览器**。
- 测试用环境变量（`NOVELSTUDIO_SCRIPT_SILENT` / `NOVELSTUDIO_NO_BROWSER` / `NOVELSTUDIO_NO_START` /
  `NOVELSTUDIO_READY_TIMEOUT_SEC`）只用于离线验证，不改变正常行为。
- 证据：`test-1018-startup-readiness.mjs` E 组（非法端口/被占/超时/已就绪 4 种场景）。
- 说明：脚本内的注释与提示是 **ASCII 英文**——`.cmd` 在 GBK 控制台下解析 UTF-8 中文会把
  字节误认成命令分隔符（本轮实测导致脚本自身报错），因此保持 ASCII。

### P07 监听错误与就绪状态 → 已修复

- `PORT` 非法 → 明确报错并退出 1；`server.on('error')` 区分 EADDRINUSE / EACCES / 其他；
- 新增 `GET /api/health`（进程活着）与 `GET /api/readiness`（可提供完整服务，含迁移状态）；
- 未就绪期间写请求一律 503；初始化异常 → 打印原因并退出 1（不进入可写状态）。
- 证据：`test-1018-startup-readiness.mjs` C/D 组。

### P08 过期分析任务覆盖当前结果 → 已修复

- `service.mjs` 新增 `analysisFenceVerdict`：完成/失败回调必须携带当前 attempt 的
  `request_id`（+ attempts）；不匹配返回 `stale` 且**零副作用**；
  同一 attempt 重复完成返回幂等回执（不重复写事件）；新 attempt 完成后旧 token 仍被拒。
- `analysis.mjs` 的调用点全部传入 `begun.analysis.request_id/attempts`。
- 证据：`test-1018-analysis-fencing.mjs`（无 token/旧 token/attempt 不符均 stale；事件数 0；
  正确 token 写入；重复完成事件数不变）；`scripts/test-temporal-refactor.mjs` 15/15 通过。

### P09 非流式 AI 响应无字节上限 → 已修复

- `readAIResponseText`：声明 `Content-Length` 超限立即拒绝；chunked 边读边计并中止；
  上限默认 8MB（`NOVELSTUDIO_MAX_AI_RESPONSE_BYTES` 可覆盖）；错误消息限长 600 字符。
- 证据：`test-1018-ai-privacy-limits.mjs` B/C 组（4MB 声明 / 8×512KB chunked 均 502，进程存活）。

### P10 调试追踪可能保存 AI 正文 → 已修复

- `traceAI`/`traceHarness` 的 AI 结果改用 `shapeOfAIResult`：**任何长度都不保留原文**，
  只留类型/长度/状态；AI 错误只留 name/code/status/message_len（不落 message/stack）；
  `endpoint` 经 `sanitizeEndpoint` 去掉 URL 账号密码与 query 值。
- 证据：`test-1018-ai-privacy-limits.mjs` E/F 组（JSONL 不含正常/错误正文与 key；仍保留 model/status）。

### P11 参数与归属校验不统一 → 已修复（关键路径）

- 新增 `ai/http/validation.mjs`（严格正整数 / 可空 / LIKE 转义）；`parsePositiveInt` 全库单一实现；
- `GET /api/search` 的非法 `work_id` 不再退化成全库检索（400）；
- `validateOwnership` 对"给了但不是正整数"的外键直接 400（以前静默跳过）；
- 证据：`test-1018-input-search.mjs` A/B/E 组。

### P12 投影 outbox 崩溃恢复与持续 drain → 已修复

- 新增 `server/services/projection-outbox.mjs`：条件更新原子认领 + `worker_token`/`lease_expires_at`；
  done/failed 必须持有 token；启动与每 60s 的持续 drain 走 `drainUntilIdle`
  （无 pending / 预算用尽 / 外部失败退避时停止）；
- `db.js` 增量迁移补两列（`worker_token`、`lease_expires_at`，默认空串，向后兼容）。
- 证据：`test-1018-projection-outbox.mjs`（6/50/100 全排空；失败只试一次；过期 running 恢复；
  旧 token 不可写；真实实例重启恢复，attempts 递增）。

### P13 迁移失败只告警 → 已修复

- `db.js` 迁移失败（除 `duplicate column` 幂等跳过外）→ 打印失败 migration id 并**抛错退出**；
  判据抽到 `ai/db-migration-failfast.mjs`（可离线断言）。
- 证据：`test-1018-startup-readiness.mjs` A/G 组（真实迁移失败：退出码 1、错误含 migration id、
  失败迁移未记账——事务整体回滚）。

### P14 AI 上下文重复装配 / 记忆响应过大 → 只测量，不改（按方案要求）

- 合成数据（20 角色 / 1 条长期记忆）三个规模实测：
  40 章 冷 p50 8ms（装配 3,995 字）；1,000 章 冷 p50 9ms（4,916 字）；10,000 章 冷 p50 60ms（5,043 字）。
  装配字数随章节数几乎不增长（有界窗口），热路径 10,000 章 p50 28ms / p95 113ms。
- 结论：1,000 / 10,000 章规模下仍没有观察到需要优化的重复装配开销；**不**删减长期记忆字段、**不**改装配结构。
- 详见 `docs/v1.2.0-p16-p14-decisions.md`（含三规模完整表格与遗留风险）。

### P15 搜索候选前 200 条遗漏 → 已修复

- LIKE 的 `%`/`_`/`\` 正确转义（`ESCAPE '\'`）；
- 候选集**先按相关度排序再截断**（上限默认 2000，可配），高相关记录不再因插入顺序被前 200 条挤掉。
- 证据：`test-1018-input-search.mjs` C/D 组（250 条低相关 + 1 条精确名，精确名进 Top1；
  `100%` 只命中字面量，不命中 `1000号`）。

### P16 自定义 AI provider 边界 → 最小收紧（产品决策已记录）

- 作者直连任意 http/https provider 仍是受支持功能（本地/私网不被一刀切拦截）；
- 地址不得内嵌账号密码；模型通道不得自带 `base_url`/`api_key`（必须用作者 `config_id`），
  消息条数 ≤50 / 总字节 ≤2MB；AI 请求 `redirect: 'error'`（非流式与流式两条通道都不转发凭证）。
- 证据：`test-1018-ai-provider-boundary.mjs`（协议/凭证位置/模型通道/302 不转发，25 条断言）。
- 详见 `docs/v1.2.0-p16-p14-decisions.md`。

### P17 单体路由拆分 → 本轮不做（方案 §7 明确为 P3 非阻塞）

- 方案原文：「本轮不进行整体重写……P17 采取渐进式拆分」。
- 本轮已按该方向抽出 3 个低耦合模块（`ai/http/origin.mjs`、`ai/http/validation.mjs`、
  `server/services/projection-outbox.mjs`），但不做整体路由迁移。

## 2. 对调用方的兼容性变化（安全收紧，均有明确错误码/文案）

| 变化 | 外部表现 | 迁移建议 |
| --- | --- | --- |
| 模型通道访问作者决策路由 | 403 | 改为作者在界面操作；或走提案/审批 |
| 模型通道 /api/ai 不带 config_id | 403 | 使用作者配置的 config_id |
| 同机不同端口页面写请求 | 403 | 从工作台自身页面操作（或使用宿主能力令牌的 CLI） |
| 畸形 JSON / 超大请求体 | 400 / 413（不再静默执行） | 修正请求体 |
| 非法数字 ID / 跨作品引用 | 400 | 传正整数且同作品 |
| 未就绪期间写请求 | 503 | 等待 readiness 200 |
| 非法 PORT / 端口占用 / 迁移失败 | 进程退出码 1 + 明确原因 | 修配置/端口/迁移后重启 |
| AI provider 非 http(s) / URL 内嵌凭证 | 400 | 修地址，凭证填 API Key 字段 |
| AI provider 返回 3xx | 请求失败（不再跟随） | 直接填写最终地址 |
| 追踪文件不再含 AI 正文 | 调试可见信息减少 | 用模型/耗时/状态/长度判断 |

## 3. 数据库迁移与回滚

- 新增迁移（幂等、事务化、有账本）：`projection_outbox.worker_token`、`projection_outbox.lease_expires_at`。
- 无破坏性 schema 变更；旧库首次启动自动补列。
- 迁移失败 → 事务回滚且**不记账**、进程非零退出（P13），不会进入半迁移可写状态。
- 代码回滚：按任务粒度 `git revert`；新增列保留不影响旧代码（默认空串）。
- 投影数据：核心 SQLite 仍是权威来源，投影可按 `dedup_key` 安全重建。

## 5. 未做 / 剩余风险（如实登记）

1. **P14 的规模基线**：已补测 1,000 / 10,000 章（冷 p50 9ms / 60ms、装配字数 4,916 / 5,043，有界窗口）；
   样本是合成数据，真实作品实体密度更高，仍建议上线后观察 p95。
2. **P16 的产品边界**：未引入 provider 白名单/域名信任列表（本地单作者场景会误伤自建服务）；
   若将来支持多用户或远程访问，需要重新评估。
3. **P12 的外部服务不可用路径**：只验证了"失败退避、不忙循环、不假成功"；
   真实 OpenViking 恢复后的批量排空需要外部服务可用时再演练。
4. **P06 的提示语言**：`.cmd` 为 ASCII 英文（GBK 控制台下 UTF-8 中文会被解析成命令）。
5. **P17**：整体路由拆分仍未开始（按方案为 P3 非阻塞）。
6. **模型通道的 AI 调用**：现在要求 `config_id`；若历史上有插件直接内联 `base_url` 调 `/api/ai/*`，
   会收到 403——需要在插件侧改（本轮仓库内插件未使用该端点）。
