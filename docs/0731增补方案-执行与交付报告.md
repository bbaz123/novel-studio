### 1.2 §3 的四处真实缺陷（都有失败断言复现）

1. **`100%` 从数字内部截取**：旧 `PERCENT_RE` 整数部分只允许 1–2 位，`100%` 会匹配到 `00%`；
   值 `0` 又被 `v > 0` 丢弃 → **100 整个消失**。
2. **`123%` 截出 `23%`**：缺左边界断言。
3. **`0%` 被丢弃**：`v > 0` 把合法零概率排除在外。
4. **`百万分之一啊。那你说，江陵这种地方一年能出一个吗？`**：`PROBABILITY_CONTEXT_RE` 里含
   「分之」这个任意 2 字子串 → 收出 `[1, 0.0001]` → 误报“应为 100%”。

修复后：`PERCENT_RE = /(?<![\d.])([0-9]{1,3}(?:\.[0-9]{1,4})?)\s*[%％]/g`，
`isValidPercentValue` 改为 `>= 0 && <= 100`（零合法），稀有度词不做概率语境检查。

### 1.3 一处**静默判据失效**（本方案之外发现，已修）

`gradeBefore` 用 `win.match()` 取窗口内**第一个**等级标记，导致一句里五个数值全被标成 `D`，
“五档齐全”**永远判不出来**。改为取窗口内**最后一个**匹配（回看 96 字符）。

> 同类坑在本文件已是第三次（前两次是 `nearestName`、`labelFromWindow`）：
> **窗口内定位实体一律取“最近”，不用 `match()` 的“第一个”。**

### 1.4 一处本会话自查发现的自身缺陷（已修）

`scripts/ci-offline-checks.mjs` 的 EPERM 回退用 `fs.mkdtempSync('.ci-out-*')` 建临时目录，
靠 `finally` 清理。**进程被中断时 `finally` 不执行** → 残留 `.ci-out-7bTRoL/`，
且未被 `.gitignore` 覆盖 → 出现在 `git status` 并让 `verify-phase-map` 报“改动没有归属”。

修法：脚本启动时 `sweepOrphanOutputDirs()` 幂等清扫上一轮残骸 + `.gitignore` 加 `.ci-out-*/` 兜底。

**两次验证**：① 假宿主接缝探针 4/4（带会话→传出会话策略；无会话/未接线→`undefined`；解析抛错→降级不失败）；

**两条操作经验（写给下一次）**：插件是宿主进程内模块，**改源码后必须重启 DSH 才生效**，判定是否已加载要比对

### 4.2 根因链（已闭合到可复核的代码位置）

这条链路每一环都有本地证据，不是推断：

1. **不是文件策略问题。** 在"文件策略＝`danger-full-access`、批准提示已禁用"的条件下重跑，门禁仍 37/17、17 处 `spawn EPERM`。
2. **不是我的代码问题。** 同机同码同命令，我这边 `EXIT=0`、54/54、0 处 EPERM。
3. **门禁第一层 spawn 是成功的。** 它拿到了 2MB 真实输出（含逐条耗时），说明 `gate → pnpm → 聚合器` 这一跳通了。
4. **失败发生在"孙进程"层。** 宿主源码里那句注释是精确线索：
   `.../dsh-sandbox-windows-acl/lib/types-Cl_DXjhk.js:792` —
   **"piped-stdio grandchild spawn"**。
   即：`pnpm`（受限 token）→ 聚合器 → 17 个检查各自的 `spawn/spawnSync/execFileSync`（用管道 stdio）→ **EPERM**。
5. **DSH 自己的工具文档写明这是受限模式的既定边界**（`dsh-tool-pwsh/lib/index.js:257`）：
   "In both confined modes, programs cannot open named pipes, so a command that captures another program's output
   through piped stdio (Node.js `child_process.spawn`/`exec` with the default `stdio: 'pipe'`) fails with EPERM,
   while `stdio: 'inherit'` and `stdio: 'ignore'` spawns work"。
   我用 `stdio:['ignore', fd, fd]`（文件重定向）的聚合器回退能跑通，也印证了这条边界描述准确。
6. **门禁插件没有请求沙箱**：`lib/host/execution.js:120` 的 `shell.resolve({...})` **没有传 `sandbox` 字段**（结果里 `sandbox: null`）。
   限制来自宿主 `shell` 服务对插件发起的执行所施加的默认受限 token。
7. **沙箱模块没有 mode 开关**：`dsh-sandbox-windows-acl/lib` 内搜不到 `readonly/workspace-write/danger-full-access` 之类的模式判定；
   唯一相关环境变量是 `SUBPROCESS_CONTROL_ENV`（控制管道交接时 `stdio` 是否带 `control` 文件描述符），**不是关闭沙箱的开关**。

**因此**：这一项**无法通过修改被授权范围内的任何文件修复**——既不能改 DSH 内核（项目规则禁止），也不能改验证门插件（绕过门禁被禁止）。
它是一条"宿主平面"的既定边界。

**17 条失败的 API 分布（已实测清点）**：`spawn` 11 个、`spawnSync` 2 个、`execFileSync` 2 个。
其中 11 个 `spawn` 是"起隔离实例 `server.js` 并用 `stdio:['ignore','pipe','pipe']` 收集输出"这一同形写法
（如 `.p1-baseline/test-editing-rules.mjs:201-212`）。

**一条已被评估但在本项目内不宜采用的路（留档供决策，不擅自实施）**：
在 `scripts/ci-offline-checks.mjs` 里为子检查注入 `NODE_OPTIONS=--require <项目内预载>`，
