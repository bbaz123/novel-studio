# v1.2.6（未发布）· 六项审稿漏修与语义闭环

> 对应方案：`Novel_Studio_六项审稿漏修与语义闭环_最新源码适配解决方案.md`（2026-10-21）。
> 本文记录**本机实际执行结果**：改了什么、为什么、证据在哪、哪些没验证。
> 版本号仍为 `1.2.5`（`frontend-test.mjs` QC-36 钉住了它）；行为变更见 `docs/CHANGELOG.md`。

## 一、真正的根因（不是"提示词不够好"）

作者看到的现象是：第一章的六条审稿意见，修稿后 1 条 PASS、1 条 PARTIAL、3 条 FAIL、1 条待核验。
本机只读核查 + 一条不花钱的探针，把链路拆成四段，断口全在上游：

| 断口 | 证据（本机真实数据） | 后果 |
|---|---|---|
| 引文核验拿"当前章节"当底本 | `chapter_reviews#29`：`base_text` 3941 字含全部引文；`chapters#119` 当前 3697 字已不含「四行字」；`counts={accepted:0,rejected:6}` | 六条 finding 全被拒收 → `findings=[]` |
| 审稿提示词与结构层白名单不是一套字段 | 落库的 `rejected[].errors` 逐条写着「缺少 kind / suggested_action / rationale / reading_cost」 | 即便引文对得上，也会因形状被整条丢掉 |
| 勾选编号 ≠ finding id | 勾选是 `issues` 下标（`1`…`6`），finding id 是 `R-0001`；`revision-findings.js` 已加载但全仓库无人调用 | 有证据也当没证据 |
| 验收层只问"字符变了没" | 无逐字证据时六项全走 `issues` 文本重写 | Q03/Q06 完全没动、Q04 改到无关动作 |

一句话：**修稿器那一轮一条逐字证据都没拿到**，它只能照自然语言问题整段重写。
所以这轮修的是"证据能不能到、到了之后判据能不能分清"，不是再写一版修稿提示词。

## 三、六项判据（离线夹具的真实输出）

| Q | 用户提供的修后差异 | 软件判定 | 原因码 |
|---|---|---|---|
| Q01 | 只把「四行字」改成「结果」，「那四个字」仍在 | `PARTIAL` | `PARTIAL_REFERENCE_AMBIGUITY_REMAINS`（risk 级子条件） |
| Q02 | 删掉值班室灯比喻，保留搪瓷盆 | `ISSUE_VERIFIED` | `ISSUE_VERIFIED` |
| Q03 | 原总结段完全未动 | `UNRESOLVED` | `REDUNDANT_EXPLANATION_REMAINS`（模型谎报 pass 也压不过） |
| Q04 | 只删「看了一眼他的表情」 | `UNRESOLVED` | `UNRELATED_CHANGE`（补丁没碰到任何一条重复劝慰证据） |
| Q05 | 正文没有新增表达 | `AWAITING_SEMANTIC`（待核验，不算通过） | `EXTERNAL_CONTEXT_REQUIRED`；有核对结论时为 `NOT_APPLICABLE_WITH_EVIDENCE` |
| Q06 | 只有王磊提普通大学 | `UNRESOLVED` | `REQUIRED_CHARACTER_DECISION_MISSING` |

**这三条不变量是这轮的重点**：
1. `actual_change=true` 只证明"文字变了"，必须再过 `all(acceptance.conditions)` 才可能 PASS；
2. 没跑语义复验 → 最多 `AWAITING_SEMANTIC`，**永不计入通过**；
3. 外部资料项（角色卡/词条/时点）既不改正文凑数字，也不自动改卡片。

## 五、没有验证 / 没有做的事（不得当成已完成）

- **没有对真实模型跑一次六项修稿**。那要付费，且本轮要证明的是"判据能识别伪修复"，
  离线夹具已经覆盖；真实模型每次是否把六条都改好，本来就不该由这个仓库承诺。
- **没有在真实浏览器里点完六项**。页面级检查走的是 `frontend-test.mjs` 的 vm + DOM 桩；
  真机复现需要一条真实修稿运行（作者的库里现在没有可复用的一次完整回执）。
- **没有新增 `AUTHOR_CONFIRMED` 状态**。它会动 `N = P + F + U + B` 的恒等式、回执与 DSH 插件契约，
  属于另一轮；现有的「作者确认：跳过复验直接合并」仍是 `PERSISTED_UNVERIFIED`，
  每个问题行仍显示"待复验"，界面不冒充"通过"。
- **Q05 的"四次"到底是画外计数还是资料时态错误，仍未定论**：本机 `characters` 表没有
  `effective_chapter`/`as_of` 字段，只有 `updated_at`，所以软件只能判"待核验"，不能替作者裁决。
- **历史报告 `#29` 已经被写坏了**（`findings=[]` 已落库）。本轮修的是"以后不再这样"，
  不会凭空复活那一轮的 rejected 条目；作者需要重新审稿一次才能拿到逐字证据。

## 六、回滚

- 全部改动的阶段归属见 `docs/phase-map.md`（由 `verify-phase-map.mjs --write` 生成）。
- 代码回滚：`git checkout -- <上表文件>`；本轮**没有数据库迁移**，`data/` 未写入（只做了一次
  `VACUUM INTO` 只读快照）。
- 回滚后旧行为立刻恢复：引文仍按当前章节核验、形状缺陷仍整条拒收 —— 也就是"六项漏修"会回来。
  因此不建议单独回滚本轮的 `server.js` / `narrative-review.mjs`，那两处是根因修复。
