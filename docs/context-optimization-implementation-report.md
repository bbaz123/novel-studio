## 预算核算与更正（2026-09-13 复核）

### 更正一：`mode=settings` 在生产路径上省掉的不是章节内容

原报告称「章节越成熟差距越大：蓝图/前文衔接/场景层最多 ~6.7k 字」。**该说法不成立。**

复核调用链：

- `public/app.js` 的 `genWorkContextBlock()` 请求的是 `/novel/context?work_id=…&mode=settings`——**新旧代码都只传 `work_id` 与 `mode`，从不传 `chapter_id`**；
- `server.js` 的 `/api/novel/context` 路由里 `const chapterId = Number(query.chapter_id) || null` **没有兜底取最新章节**；
- 因此 `buildNovelContext` 里 `chapter` 恒为 `null`，被跳过的三层实际只渲染出占位符：
  - 当前场景 → `（未指定具体章节）`
  - 本章蓝图 → `（暂无蓝图，可在工坊里用「AI 写作」自动生成，或直接成文）`
  - 前文衔接 → `（无）`

结论：`mode=settings` 在该调用点**只去掉了约几十字占位符噪音**（实测合计差 531 字，其余来自预算收紧），不是「最多 6.7k 字」。那个数字仅在**显式传入 `chapter_id`** 时才成立——冒烟测试 3b 组恰好传了 `chapter_id`，所以它覆盖的是模式语义，而非生产调用点的真实收益。

**本批优化的真实收益来自另外两项**：提问轮极简上下文（~24.5k → ~100 字）与词条库 top-12（11,509 → 2,177 字）。`mode=settings` 本身无害且方向正确，但不应被当作主要收益来源。

### 更正二：12,000 字预算数学上不可达 → 终审修正为 18,000 字

settings 模式固定层 cap 合计：

| 层 | cap（字） |
|---|---|
| 作品 | 900 |
| 长期记忆 | 2,200 |
| 相关记忆检索 | 1,400 |
| 最近事件 | 1,800 |
| 未闭合伏笔 | 1,200 |
| 人物关系 | 800 |
| 写作风格红线 | 4,000 |
| **合计** | **12,300** |

再加弹性层最低 800（大纲 400 + 世界观 400）与出场角色卡（build 上限 4,000），**下界约 17,600 字（含层标题注记）**，远超 12,000。而收敛循环只收缩弹性层，缩到底即停止——原常量 12,000 是**永远无法执行的误导性数字**。

**终审修正（2026-09-13）**：`TOTAL_BUDGET` settings 分支改为 **18,000**。理由：

1. **诚实性**：18,000 = 质量层全保底时的可执行下限，收敛循环真正能完成它的工作；
2. **质量更优**：质量层仍永不加入弹性收缩（novel_lookup 关键词检索覆盖不到长期记忆/事件账本，收缩即不可查回的真实损失——「零损失」机制不变）；相比旧常量，1.2 万–1.8 万字的中等作品**不再被无谓地把大纲/世界观压到 400 字**，内容保留更多；
3. **测试锁定**：冒烟测试新增「大作品 settings 装配 ≤ 18,000 字」断言（真实 120 章 × 50 角色数据），防止常量再次失准；层构成断言（3b 组）继续保留，作为「零损失」的语义不变量。

> **修订记录（2026-09-13 自审）**：该断言曾先改为长度比较（`settings` 不长于 `full`），但那一版本身也不安全——被截断的层会附加「本层共 N 字，已按预算截断」提示（约 40 字/层），提示文本可能让该层反而长于未截断时；当章节层内容近乎为空时，长度比较的余量只剩约 9 字，随时可能假失败。层构成与数据规模、截断提示都无关，故最终采用层构成断言。**教训：替换一个脆弱断言时，必须确认新断言本身没有同类的边界缺陷。**

### 更正三：可发现性与关键词提取补强

- **可发现性**：词条库改 top-12 后，原提示只写「其余可用 novel_lookup 查证」却**不列出被省略的条目**——模型无法索要它不知道存在的东西，「按需查回原文」的零损失承诺缺了这一环。现已在提示中附上未选入条目的**标题清单**（上限 80 条，每条约 5–10 字，成本可忽略），仅超出 80 条时降级为计数。
- **`extractKeywords` 两处缺陷**：①旧实现对中文长句生成全部 2 字滑窗且不做过滤，「一个 / 我们 / 可以」这类通用词会主导打分，使 top-12 选取接近随机——现加入通用二字组合停用词（刻意不含角色 / 设定 / 剧情 / 世界观等领域词）；②旧实现凑够 60 个关键词就 `break`，长请求的后半段完全参与不到打分——现扫完全文后按词频排序取前 80。
