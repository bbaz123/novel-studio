| | 内容 | 状态 |

## 2. 语料设计（`tests/quality/corpus.json`）

- **全部合成文本**，两个合成作品（`W1 合成样本·甲` 8 章 / `W2 合成样本·乙` 6 章），
  零作者私人正文；套件里有专门的断言扫描路径/邮箱/密钥样式的串。
- **25 条用例覆盖 12 类**（每类 ≥2）：

| 类别 | 考什么 | 例子 |
|---|---|---|
| `chapter_tail_fact` | 章尾才落地的关键事实 | 「我明日要去北关」 |
| `identity_alias` | 别名不是新实体；改名不换 ID | 「九爷」= 沈九 |
| `relation_direction` | 关系有方向，反了就是另一件事 | 「我欠你一条命」 |
| `misbelief` | 角色**相信**的不等于事实 | 陆迟确信陈默告密（第 3 章被推翻） |
| `narrative_boundary` | 回忆 / 梦境 / 转述不是现在时事实 | 梦里那句「别回来」 |
| `future_isolation` | 未发生的事不能当现状 | 「明年春天去南边」≠ 已到南边 |
| `negation` | 否定不能抽成肯定 | 「你不欠」/「并不是他的妹妹」 |
| `intra_chapter_contradiction` | 同章前后矛盾要以结尾为准并标记 | 说留下却走了 |
| `state_overflow` | 互斥状态必须覆盖不能并列 | 既已离开又已回来 |
| `revision_change` | 修订后旧值必须标记过时 | 北关 → 南关 |
| `partial_failure` | 只抽到一部分必须标 partial | `expectStatus: partial` |
| `stale_proposal` | 旧修订的提案必须被拒 | 引文已不存在 |

## 3. 标注规则（`tests/quality/gold.json`）

按**可判定**的东西标注，不做文本相似度：

- `entityId`：同名不同人必须不同 ID；改名不换 ID；别名指向同一 ID。
- `field` + `prev` + `next`：状态字段与前后的**具体值**；`next: null` 表示"该状态被清空"（合法语义，不是缺字段）。
- `evidence {chapterId, quote}`：引文必须**在被引章节正文里逐字出现**（机器校验）。
- `temporality` / `boundary`：`current` / `recalled` / `dream` / `future`。
- `mustNot`：明确写了"抽成什么样就算错"，用来表达否定、方向、越界这类硬约束。

## 4. 评分指标（`scripts/nsdsh/score-quality.mjs`）

| 组 | 指标 | 门禁 |
|---|---|---|
| 结构覆盖 | 必填字段齐全率 | **必须 1.0** |
| 证据 | 引文逐字可定位率 | **必须 1.0** |
| 事实质量 | precision / recall（实体+字段+值三元组） | 报告，不设阈值（留给 Q1 由作者定） |
| 时态安全 | 严重实体错配 / 未来泄漏 / 跨作品越界 / 未确认写入正式状态 | **全部必须 0** |
| 重复与成本 | 多轮输出的分歧、token/费用 | 只有一轮时如实报"未知" |

**为什么证据阈值是 1.0 而不是 0.95**：定位不到引文的候选不是"证据"，只是一句话。
0.95 意味着 100 条里可以有 5 条**无法核对**就流向正式状态 —— 这与本项目"不让设定悄悄漂移"的
立足点直接冲突。

## 5. 套件在测什么（`tests/quality/quality-corpus.test.mjs`，12 条）

评分器最容易的病是**永远给满分**。所以 12 条里 6 条是**负向对照**：

| 用例 | 塞进去的错 | 必须观察到 |
|---|---|---|
| R04Q0-5 | 未知实体 | 严重误判 ≥1，门禁阻断 |
| R04Q0-6 | 引文正文里没有 | 证据率 <1 且阻断 |
| R04Q0-7 | 删掉 `field` | 结构不合格；同时验证 `next:null` **不算**缺字段 |
| R04Q0-8 | 跨作品 workId / `applied:true` 无审批 / `temporality:future` | 三类零容忍项各自被抓到 |
| R04Q0-9 | 值抽错 | precision 与 recall **都**下降（fp≥1 且 fn≥1） |
| R04Q0-3 | 标注自洽 | 每条 gold 的实体与引文都在语料里 |

实测：`node tests/quality/quality-corpus.test.mjs` → **12/12 通过**；
`node scripts/nsdsh/score-quality.mjs` → 自检 23/23 结构合格、23/23 引文可定位、precision=recall=1、零违规、**0 次真实调用**。

## 6. 一次真实的自我纠错（留档）

- 第一版把 `next: null` 当"缺字段"，于是 3 条"状态被清空"的合法事实被判成结构错误，
  自检直接红了 0.86 —— 说明**判据写错会同时冤枉正确结果**。
- 第一版语料里修订用例（Q19/Q20）的引文取自**修订 2 的正文**，而语料只有原稿，
  于是引文永远定位不到。修法是给语料加 `revisionTexts`，而不是放宽阈值。
- 这两条都不是"调一调就绿"，是判据本身错了。

## 7. Q1 需要的授权（本阶段**没有**自行开始）

方案 §6.1 要求作者显式批准以下全部项之后才执行：

1. **provider / 模型**（例如 `deepseek-official` / 具体型号）；
2. **样本数**（25 条全跑，还是先小批量校准）；
3. **输入内容**（只跑合成语料，还是允许抽真实章节）；
4. **人民币预算上限**（含是否沿用 ¥2.00）；
5. **是否允许上传正文**；
6. **保存哪些元数据**（脱敏要求）。

在拿到这 6 项之前，Q1 的状态是 `NOT_RUN_REQUIRES_AUTHORIZATION` ——
**不会**因为 Q0 通过就把它勾上。

## 8. 把 Q1 跑起来的方式（授权后照做）

```bash
# 1) 在"手动评测模式"下产出预测（需另行实现/接线的采集入口），写成 predictions.json：
#    [{ caseId, workId, entityId, field, prev, next, evidence:{chapterId,quote}, temporality, revision? }]
# 2) 打分（本脚本不发起任何模型调用）
node scripts/nsdsh/score-quality.mjs --predictions predictions.json --json
```

门禁为 0 的持续存在时，不得升级默认模型路由、不得把候选自动提升为正式状态；
保留零计费回归与人工写作能力。
