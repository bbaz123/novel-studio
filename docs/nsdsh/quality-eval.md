## 2. 语料设计（`tests/quality/corpus.json`）

- **全部合成文本**，两个合成作品（`W1 合成样本·甲` 8 章 / `W2 合成样本·乙` 6 章），
  零作者私人正文；套件里有专门的断言扫描路径/邮箱/密钥样式的串。
- **25 条用例覆盖 12 类**（每类 ≥2）：

| 类别 | 考什么 | 例子 |
|---|---|---|
| `chapter_tail_fact` | 章尾才落地的关键事实 | 「我明日要去北关」 |
| `identity_alias` | 别名不是新实体；改名不换 ID | 「九爷」= 沈九 |
| `relation_direction` | 关系有方向，反了就是另一件事 | 「我欠你一条命」 |
| `misbelief` | 角色**相信**的不等于事实 | 陆迟确信陈默告密（第 3 章被推翻） |
| `narrative_boundary` | 回忆 / 梦境 / 转述不是现在时事实 | 梦里那句「别回来」 |
| `future_isolation` | 未发生的事不能当现状 | 「明年春天去南边」≠ 已到南边 |
| `negation` | 否定不能抽成肯定 | 「你不欠」/「并不是他的妹妹」 |
| `intra_chapter_contradiction` | 同章前后矛盾要以结尾为准并标记 | 说留下却走了 |
| `state_overflow` | 互斥状态必须覆盖不能并列 | 既已离开又已回来 |
| `revision_change` | 修订后旧值必须标记过时 | 北关 → 南关 |
| `partial_failure` | 只抽到一部分必须标 partial | `expectStatus: partial` |
| `stale_proposal` | 旧修订的提案必须被拒 | 引文已不存在 |

## 3. 标注规则（`tests/quality/gold.json`）

按**可判定**的东西标注，不做文本相似度：

- `entityId`：同名不同人必须不同 ID；改名不换 ID；别名指向同一 ID。
- `field` + `prev` + `next`：状态字段与前后的**具体值**；`next: null` 表示"该状态被清空"（合法语义，不是缺字段）。
- `evidence {chapterId, quote}`：引文必须**在被引章节正文里逐字出现**（机器校验）。
- `temporality` / `boundary`：`current` / `recalled` / `dream` / `future`。
- `mustNot`：明确写了"抽成什么样就算错"，用来表达否定、方向、越界这类硬约束。

## 4. 评分指标（`scripts/nsdsh/score-quality.mjs`）

| 组 | 指标 | 门禁 |
|---|---|---|
| 结构覆盖 | 必填字段齐全率 | **必须 1.0** |
| 证据 | 引文逐字可定位率 | **必须 1.0** |
| 事实质量 | precision / recall（实体+字段+值三元组） | 报告，不设阈值（留给 Q1 由作者定） |
| 时态安全 | 严重实体错配 / 未来泄漏 / 跨作品越界 / 未确认写入正式状态 | **全部必须 0** |
| 重复与成本 | 多轮输出的分歧、token/费用 | 只有一轮时如实报"未知" |

**为什么证据阈值是 1.0 而不是 0.95**：定位不到引文的候选不是"证据"，只是一句话。
0.95 意味着 100 条里可以有 5 条**无法核对**就流向正式状态 —— 这与本项目"不让设定悄悄漂移"的
立足点直接冲突。

## 5. 套件在测什么（`tests/quality/quality-corpus.test.mjs`，12 条）

评分器最容易的病是**永远给满分**。所以 12 条里 6 条是**负向对照**：

| 用例 | 塞进去的错 | 必须观察到 |
|---|---|---|
| R04Q0-5 | 未知实体 | 严重误判 ≥1，门禁阻断 |
| R04Q0-6 | 引文正文里没有 | 证据率 <1 且阻断 |
| R04Q0-7 | 删掉 `field` | 结构不合格；同时验证 `next:null` **不算**缺字段 |
| R04Q0-8 | 跨作品 workId / `applied:true` 无审批 / `temporality:future` | 三类零容忍项各自被抓到 |
| R04Q0-9 | 值抽错 | precision 与 recall **都**下降（fp≥1 且 fn≥1） |
| R04Q0-3 | 标注自洽 | 每条 gold 的实体与引文都在语料里 |

实测：`node tests/quality/quality-corpus.test.mjs` → **12/12 通过**；
`node scripts/nsdsh/score-quality.mjs` → 自检 23/23 结构合格、23/23 引文可定位、precision=recall=1、零违规、**0 次真实调用**。

## 6. 一次真实的自我纠错（留档）

- 第一版把 `next: null` 当"缺字段"，于是 3 条"状态被清空"的合法事实被判成结构错误，
  自检直接红了 0.86 —— 说明**判据写错会同时冤枉正确结果**。
- 第一版语料里修订用例（Q19/Q20）的引文取自**修订 2 的正文**，而语料只有原稿，
  于是引文永远定位不到。修法是给语料加 `revisionTexts`，而不是放宽阈值。
- 这两条都不是"调一调就绿"，是判据本身错了。

## 8. 把 Q1 跑起来的方式（授权后照做）


# R04-Q1：真实模型质量评测（已执行，2026-10-17）

> **状态**：`EVALUATED_WITH_FINDINGS`（**不是**"质量达标"）
> **授权**：作者于 2026-10-17 明确给出六项 —— provider/模型=当前模型；样本=25 条全跑；
> 允许抽真实章节；预算上限 **¥10**；允许上传正文；保存**所有**元数据。
> **实际花费**：**¥0.487**（四轮合计，见 §Q1.5）。脚本自带 ¥1.5 硬护栏（同时满足用户 ¥10 与本插件 ¥2 上限）。

## Q1.1 跑的是什么

| 项 | 值 |
|---|---|
| 模型 | `deepseek-flash`（当前模型）。最终采用其**非推理入口** `deepseek-chat` —— 两次探测里响应都回报 `model: deepseek-flash` |
| 端到端入口 | `https://api.deepseek.com/v1/chat/completions`，`response_format: json_object`，`temperature: 0` |
| 样本 | `tests/quality/corpus.json` 全部 25 条（12 类） |
| 采集脚本 | `scripts/nsdsh/run-quality-eval.mjs`（**唯一会真实计费的脚本**，必须带 `--authorized-by`） |
| 打分脚本 | `scripts/nsdsh/score-quality.mjs --predictions …`（不联网、不调用模型） |
| 元数据 | `.nsdsh/quality-eval{,-focused}/raw/<caseId>.json`：完整请求/响应/usage/耗时/费用/授权说明/key 指纹（**不含 key 值**） |

**两种提示模式**（同一批 gold，因此可比）：

- **开放式**：给实体表 + 字段词表 + 到证据章为止的正文，要求"列出本章新确立的事实"。
- **定向**：额外告知目标 `entityId + field`，只要求产出「值 + 逐字引文 + 时态」。

## Q1.2 结果一：模型完全胜任的部分

| 指标 | 开放式（92 候选） | 定向（19 候选） |
|---|---|---|
| schema 合格率 | **100%** | **100%** |
| 引文逐字可定位率 | **100%** | **100%** |
| 未知实体 | **0** | **0** |
| 未来信息当现状 | **0** | **0** |
| 跨作品越界 | **0** | **0** |
| 未确认写入正式状态 | **0** | **0** |

**这是最有价值的一条**：模型在"结构化输出 + 逐字引用原文 + 不乱造实体/不越作品/不把没发生的事写成现状"
这四件事上**零违规**。对本产品"不让设定悄悄漂移"的立足点来说，这正是必须守住的那一层。

## Q1.3 结果二：值抽取与召回不行（按字面判据）

| 指标 | 开放式 | 定向 |
|---|---|---|
| precision（实体+字段+值三元组全等） | 0.033 | **0.316** |
| recall（同上） | 0.130 | **0.261** |
| 命中/候选/应有 | 3 / 92 / 23 | 6 / 19 / 23 |

**但有两点必须一起读，否则会误判模型**：

1. **开放式本来就不该按这个判据打分**：任务要求"列出本章新确立的事实"，而 gold 每条用例
   只标注**一条**目标事实。92 条候选里 40 条是"别的实体上的合法事实"（现记为 `offTarget`，
   **不算错**）。这说明的是**评分粒度与任务粒度不匹配**，不是模型错。
2. **定向模式下 13 条"错"全部是同一实体、同一字段、只是措辞不同**：

| 用例 | 模型 | gold | 判定 |
|---|---|---|---|
| Q01 / Q19 / Q21 | "明日要去北关/南关" | "明日去北关/南关" | 同一事实，措辞差异 |
| Q07 / Q10 / Q11 / Q14 | 略长但同义 | 略短 | 同一事实，措辞差异 |
| Q08 / Q13 / Q16 | `accused_by = 陆迟` / `owes_life_to = 林砚` | `next = null`（状态被清空） | **gold 口径歧义**：清空 vs 指向谁 |
| Q17 | `location = 北关城楼下` | `回程路上` | **真实差异**（取了较早章节的状态） |
| Q18 | `presence = present`（英文） | `回来了` | **真实差异**（值域未约束） |

**按"实体+字段"归一的定向精度是 19/19 = 100%**（值 100% 落在正确字段上），
其中 7 条是纯措辞差异、4 条是 gold 口径问题、2 条是真实差异。

## Q1.4 真实短板（这一节才是结论）

1. **召回不足**：25 条定向请求里 **4 条返回空**（Q04 别名、Q05 别名、Q06 误信、Q25 关系方向），
   都没抓到 gold 标注的那条事实。字段级召回 19/23 = 0.826，**字面值召回 6/23 = 0.261**。
2. **值域不受控**：会输出 `present` 这类英文枚举，与产品的中文状态值域不一致。
3. **取章位置会错**：Q17 取了较早章节的状态（`北关城楼下`）而不是本章的 `回程路上`。
4. **推理入口不可用于此任务**（见 Q1.5 第 1、2 轮）：`deepseek-flash` 的思考模式在 25 条里
   有 16–21 条把 `max_tokens` 全烧在 `reasoning_content` 上、`content` 为空。

**因此不得声称**："模型质量达标"、"可以直接自动确认状态"。当前证据支持的说法是：
**结构与证据层可用；值抽取需要更强约束（值域枚举 + 章节定位）或人工复核兜底。**

## Q1.6 评测仪自身的两个缺陷（先修仪器，再谈模型）

第一次给结果打分时得出"严重误判 40、未来泄漏 18"，随后发现**是仪器错了**：

| 缺陷 | 表现 | 修正 |
|---|---|---|
| `FUTURE_AS_CURRENT` **极性写反** | 把"模型把某条事实标成 future"当成泄漏，可那是**正确**的（"明日要去北关"里的北关确实还没到） | 只在**用例本身考 future** 而候选标 `current` 时才算泄漏 |
| `SEVERE_ENTITY_MISMATCH` **判据过宽** | 把"不是 gold 指的那个实体"判成严重错配（40 条），实际上那只是"别的合法事实" | 只保留"作品实体表里根本没这个 id"为严重项；其余记为 `offTarget`（统计而非错误） |

修正后同样的预测得到：未知实体 0 / 未来泄漏 0 / 跨作品 0 / 未确认写入 0，门禁通过。
**这条经验与本项目已有的《汇总统计口径未对齐导致覆盖率为零》同源：先怀疑仪器，再怀疑被测对象。**
