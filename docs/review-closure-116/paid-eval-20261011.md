## 2. S01：扫描命中能否被否决（**核心验证**）

### 2.1 方法

A/B 两侧使用**同一份真实提示词**——直接调用 `public/app.js` 的 `buildAIReviewPrompt`（离线 vm 装载，见
`paid-eval-build-prompts.mjs`，实测 3415/3454 字符），只替换待审正文：

- **A 侧**：`她微微侧过身，让出了一条路。他点了点头，继续往前走。`（「微微」合法用法）
- **B 侧**：`他不认识画面里那个女生。这道光柱和他没关系，这场雪和他也没关系。他站在那里，一动不动，也没有任何表情…`（真实冗余/否定句堆叠）

### 2.2 结果（真实模型输出，`paid-eval-s01-analysis.json`）

| 断言 | 结果 | 实测观察值 |
|---|---|---|
| S01-A1 合法语境的「微微」**没有**被任何 issue 定罪 | ✅ | 不存在 `signal_hit=微微` 且 verdict∈{confirmed,hypothesis} 的条目 |
| S01-A2 「微微」在 `scan_verdicts` 被判 `not_applicable` | ✅ | `verdict = "not_applicable"` |
| S01-A3 该裁决带**反证** | ✅ | `counterevidence` 长 60 字 |
| S01-A4 总评明说「微微」是正常用法、不宜硬报 | ✅ | 命中"微微…正常…不宜…" |
| S01-B1 真实冗余被报成 issue（非"零命中"放过） | ✅ | `issues = 7` 条 |
| S01-B2 至少一条 issue 指向"和…没关系／也没关系" | ✅ | 1 条 |
| S01-AB 两侧有区分力 | ✅ | A 侧不定罪 + not_applicable；B 侧 7 条 issue |

**关键原话（模型真实输出，可直接核对）**：

- summary：*"…扫描命中的"微微"在此属于正常程度副词，**不宜硬报为AI腔**。"*
- `scan_verdicts[0]`：`signal_hit: "微微"`、`verdict: "not_applicable"`、
  `counterevidence: ""微微"在此是正常程度副词，修饰侧身幅度；单句内没有形成模板复用、情绪词库轮换或AI腔复读，不能仅因扫描命中就报为问题。"`

### 2.3 这一条为什么重要

它**在真实模型上验证了本轮 S01 修改的目标行为**：扫描命中被当成**可否决的候选**，而不是"命中即缺陷"。
同时证明了 A/B 有**区分力**（A 侧放过合法用法、B 侧抓真问题），不是"一律不报"或"一律都报"。

## 3. E01 §5.2：报告自洽检测的真实对照（**未触发，如实记未证实**）

### 3.1 方法

用 `checkReportConsistency` 的**真实实现**（不是另写判据）去检验真实模型的输出是否自相矛盾。两个自然样本：

- **DOC1**：0001 号与 0372 号两段**逐字同构**的流程 → 看模型会不会一边夸"后续不再完整演示"一边报"重复"。
- **DOC2**：正文**确实存在**解释句（"他从小就觉得…"）→ 看模型会不会夸"伏笔完全没有解释"。

### 3.2 结果

| 样本 | `consistency.status` | 冲突数 |
|---|---|---|
| DOC1（重复流程） | `ok` | 0 |
| DOC2（有解释句） | `ok` | 0 |

两例都**没有**触发 `needs_calibration`。观察到的模型行为是：它的 strengths 措辞**本来就有范围限定**
（例 DOC1 strengths 第 3 条写作"重复结构**若后文兑现为**伏笔，具备延展潜力"，而不是"后续不再重复"）。

**诚实结论**：本次两个自然样本**未能复现**任务书 §1.3 记录的那类矛盾，因此
**不能声称该检测器在真实链路上已被证实有效**。它目前的状态是：
① 逻辑有离线正/反向单元测试（T05-a / T06-a / T06-b）；② 真实阳性样本**未取得**。

> 为什么不据此删掉检测器：任务书 §1.3 的那两处矛盾来自**另一份完整章节 + 当时的历史报告**，
> 本次只有两段合成样本，不构成"该矛盾不会发生"的证据。按"没有证据不判错"，保留检测器并如实标注未证实。

## 5. 本轮暴露的**装置错误**（重要，属于我自己的错误）

在分析真实回复时，我判"某扫描信号是否被定罪"连错 **3 次**，**每一次都是假阳性**，而不是模型的问题：

| 次数 | 我的写法 | 为什么假阳性 |
|---|---|---|
| ① | `JSON.stringify(整份报告).includes('微微')` | 命中 `scan_verdicts` 里那条 `not_applicable` 与 summary |
| ② | `JSON.stringify(issue)` | summary 与 issues 是**同一解析对象的并列键**，被混入 |
| ③ | 只读 issue 的 `text` | 模型**引用了原句**「她微微侧过身…」来论述篇幅，字面含「微微」 |

**最终正确判据**：读**结构化字段**——某条 issue 显式声明 `signal_hit === '微微'` 且 `verdict ∈ {confirmed, hypothesis}`
才算"被定罪"。这与本仓既有经验（"判据要落在事实字段上，不要落在文本子串上"）同源。

> 这 3 次都不是"猜想错了"，而是**同一类错误的复发**：用文本包含代替结构化判定。
> 若第一版就写进结论，我会向作者报一个**错误的负面结论**（"模型仍在误报微微"），而事实相反。
