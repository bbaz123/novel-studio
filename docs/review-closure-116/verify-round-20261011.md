## 2. N6：自洽检测的真实阳性 → **发现真实缺陷并修复**

### 2.1 做法

用 `checkReportConsistency` 的**真实实现**去跑 12 份**真实历史审稿报告**（配套章节正文从库中只读取用）。

### 2.2 修复前：**6/12 误报**（严重假阳性）

命中的配对明显不成立，例如：

| strength | 被配上的 issue | 为什么荒谬 |
|---|---|---|
| 「等级分量全靠事件给出，**不靠**旁白建体系」 | 「篇幅与节奏（全章）：超出目标 4000 字约 800 字…」 | 只共享一个「章」字 |
| 「收力比出力难…」 | 「开篇时间线与既有设定冲突…」 | 二者毫不相干 |
| 「系统与岳宸炎的对话节奏克制且**不抢**戏」 | 同一条篇幅问题 | 同样只共享零星字 |

**根因**：`ABSOLUTE_CLAIM` 里写了 `/(完全|彻底|根本)?(没有|没|无|不)/` —— 前缀**可选**，
于是**裸 `不`** 就算"绝对措辞"；而中文里 `不靠/不是/不锁/不抢` 极其常见 → 6/12 假阳性。

### 2.3 修复过程（两次修正，都留痕）

1. **去掉裸 `不`**，只认完整穷尽式表述：`不再…` / `(完全|彻底|根本|基本)(没有|没|无|不存在|不)` /
   `(从没|从未|从来没有|一处也没有|毫无|没有任何)` / `零(解释|重复|说明|遗漏)`。
   → 误报 **6/12 → 1/12**。
2. **1/12 仍存**：把"同话题"从"共享任意 2-gram"收紧为"共享 ≥3 个 2-gram 且重叠系数 ≥0.18"
   → 真实数据 **0/12**，但**合成正例 T05-a 变成假阴性**。

**这里得出关键结论（本轮最有价值的一条）**：
> 在"长真实报告"上要收紧、在"短合成正例"上要放宽 —— **不存在同时满足两者的字面阈值**。
> 也就是说：**字面重叠根本无法证明"语义互相矛盾"**。

### 2.4 最终设计（改了契约，而不是调参）

- `status: 'needs_calibration'` **只在可确证时给出**：绝对措辞 × **正文反例**（证据就是那句原文）——
  即 `strength_vs_body`。这是唯一能给出可核对证据的判定。
- `strength_vs_issue` 的话题重叠降级为 **`advisories`（建议核对）**，**不改变 status**，措辞明确写
  "本层不做语义判断，因此不据此宣称报告自相矛盾"。

### 2.5 结果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 真实数据假阳性 | **6/12** | **0/12** |
| 合成正例（可确证那类） | 通过 | 通过（T06-a） |
| 合成负例 | 通过 | 通过（T06-b） |
| 单位断言 | — | **32/32**（新增 T05-a 改述 + **T05-b 假阳性回归**） |

> **T05-a 我改写了它的断言**。原断言要求 `status=needs_calibration`，那是**旧契约**；
> 新契约下它应进 `advisories`。我没有删弱它，而是把它改成断言新契约
> （`status=ok` + `advisories≥1` + `conflicts=0` + note 说明不据此宣称矛盾），
> 并**新增 T05-b** 把"不靠旁白建体系"这个真实假阳性永久钉住。

## 8. 闭环修复（作者「修复未闭环问题」）

作者指出"未闭环"。按[自查发现的缺陷没有闭环]的判据自查，**确认两处正是我自己制造的
「只修数据层、不修呈现层」**：§2 把 `strength_vs_issue` 从 `conflicts` 降级到 `advisories` 时，
只改了数据层，**呈现层没跟着改**。

### 8.1 缺陷一：advisories 从未被渲染（信号在界面上彻底消失）

- **现象**：`ai/editing/narrative-review.mjs` 产出 `advisories`，但 `public/app.js` 的
  `reportConsistencyHtml` 只读 `conflicts`（全仓 grep `advisories` 只命中 narrative-review.mjs）。
  → 上一轮"降级为建议核对"这个设计**在界面上等于没做**：作者什么也看不到。
- **先写失败测试**：`S04-2a`（advisories 必须渲染）先红 —— `{"rendered":"","len":0}`。
- **修复**：`reportConsistencyHtml` 同时渲染两档，且**措辞强度必须区分**：
  `conflicts` 说"互相否认/请校准措辞"；`advisories` 只说"建议核对（非结论）"，
  并明写"本工具不据此判定报告矛盾"。
- **顺带修掉**：我第一版修复文案里写了字面 `**`（该仓有专门的 Markdown 泄漏断言 107c），已改为纯文本。

### 8.2 缺陷二：回读路径下 consistency 的层级不一致（落库后提示静默消失）

- **现象**：自洽结论在两条读路径上放在**不同层级**——
  新建路径挂在 `report.consistency`（保存响应回填），落库报告里也在 `consistency`，
  但 `openLastReview()` 把 **`report` 整个**交给 `showReviewReport`，
  而 `reportConsistencyHtml` 只当"一致性对象"读 → 回读时**顶层没有该字段 → 提示静默消失**。
  "落库后仍可追溯"因此只在**数据层**成立。
- **先写失败测试**：`S04-2d` 覆盖"传进来的其实是报告对象"这一形状。
- **修复**：渲染器两种形状都认（`consistency.consistency` 或 `consistency` 本身）。
- **另**：`server.js` 增 `consistency_advisories` 计数，且**与 `consistency_conflicts` 分开**——
  合并计数会把"建议"说成"结论"。

### 8.3 闭环后的验证（全部实测）

| 断言 | 覆盖 |
|---|---|
| `S04-2a` | 缺陷一：advisories 必须渲染 |
| `S04-2b` | advisories 措辞不得像 conflicts 那样指控矛盾 |
| `S04-2c` | 阴性对照：两档皆空时不出现该区块 |
| `S04-2d` | 缺陷二：报告对象形状（回读路径）同样渲染 |

结果：`frontend-test.mjs` **ALL PASS**；`narrative-repair` **11 套件 / 240 条断言 0 失败**。

### 8.4 这一轮的可复用教训

> **当**把某个信息从 A 字段搬到 B 字段（哪怕是"降级"）**时 → 必须**枚举该字段的全部消费面**
> （数据层 / 呈现层 / 落库后回读路径 / 计数与 API 暴露），逐个确认仍读得到 →
> 否则"改好了"只在数据层成立，用户在界面上一无所获。

这与[自查发现的缺陷没有闭环]的形态 B 完全相同；**本次是复发**，值得记入长期经验。
