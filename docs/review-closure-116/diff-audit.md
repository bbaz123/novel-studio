> 来源：任务书 §1.1 给出的**审稿前 → 审稿后**六组差异（`SOURCE`）。
> 纪律（§8 E04）：**只评价实际触达的 diff**；"改了 6 组"**不等于**"修复了 6 个问题"。

## 0. 判定口径

| 标记 | 含义 |
|---|---|
| `local_improvement` | 该处改动**自身**减少了冗余/解说，可证 |
| `partial` | 只解决了父问题的一部分（父问题仍未解决） |
| `protected_kept` | 该处是必须保留的伏笔/事实，**不得**因"减字"被删 |
| `not_verified` | 缺完整正文或运行记录，无法证实 |
| `template_risk` | 存在"删一个解释 → 补一个感官/微动作"的模板替换倾向，需核验 |

## 3. 组合核验与保护

- **单条安全 ≠ 合并后安全**：D01–D06 中任何两条单独成立，合并后仍须过组合门禁（`reference_anchor` 等硬码）。
  证据：`08-authorization` E01-5b（两条各自在授权跨度内、合起来删光先行语仍被抓到），`01-patch-protocol` P08。
- **必须保护的伏笔与事实**（本轮未见证被破坏，列此作为红线）：
  0731 号码纸正式折一道、林清雪看掌心、系统只出现一次且"不知道系统功能"、S级/SS级与海澜/江陵的地点区别、
  检测结果与画面、王磊与岳宸炎各自的说话方式。
- **不得以"不达 4000 字"为由破坏已批准设定或伏笔**（任务书启动指令明写）。

## 4. 本轮实际源码 diff 的影响面（与 D01–D06 区分）

D01–D06 是**用户那一章的正文改动**；本轮的源码改动是**机制层**，不触碰任何章节：

| 源码改动 | 是否会改变已有章节正文 |
|---|---|
| S01 审稿提示词候选化 | 否（只影响**以后**审稿时模型被要求怎么做） |
| 报告自洽检测 | 否（只读核对 + 报告展示） |
| 两类新诊断（候选层） | 否（只产出候选；`requires_semantic_check: true`，不产生可直接应用的补丁） |
| S05-1 fail-closed | 否（只在"期望 v2 且缺授权表"这种输入下拒绝执行；正常作业带授权表） |
| 差异预览篇幅缺口 | 否（只显示数字） |

结论：本轮源码改动**不会**自动改写任何既有章节，符合"不得修改真实小说"的边界。
