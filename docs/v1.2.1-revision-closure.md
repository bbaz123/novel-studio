# v1.2.1 审稿质量闭环（实现报告）

> 输入方案：《Novel Studio v1.2.1 审稿发现问题却未充分修复：源码级根因分析、质量闭环与 DSH 插件联动改造方案（1）.md》
> 本文件记录**实际改了什么、怎么验证、哪些没做**。凡是没跑过的都不写成通过。

## 一、要解决的四个缺口（方案 §1.2）

| 缺口 | 原状 | 本轮处置 |
| --- | --- | --- |
| A 审稿输出没有机器可用契约 | 只有 `issues:[{text}]` | 审稿提示词新增 `findings[]`（稳定 id / 类型 / 严重度 / 逐字证据 / 验收判据），**保留 issues** 给旧界面；`public/revision-findings.js` 负责归一化与诊断 |
| B 一条问题只取第一个引文、只给一个热点 | `buildRevisionPlan` 命中即 `break` | 新增 `buildRevisionPlanV2`：任意多处**只读证据** + 多处**逐一授权**的编辑目标 + 同一问题原子组；v1 原样保留 |
| C 应用成功 ≠ 问题修复成功 | `coverage_ok` 只排除 `unaccounted` | 新增 `public/revision-semantic-verifier.js`：确定性层 + 语义层逐条裁决；`ISSUE_VERIFIED` 只来自语义通过 |
| D 语义闸已存在，但 UI 传 `semantic:null` | 预览固定传 null | 预览改传逐条结论；语义未运行只能显示"待语义复核"；新增作者显式触发的一次付费复验 |

## 二、新增模块（纯函数，浏览器与 Node 共用）

- `public/revision-findings.js`（finding.v2）
  - `normalizeReviewReport` / `normalizeFinding` / `findingsFromIssues`；
  - 证据逐字校验：出现次数、唯一性；`QUOTE_NOT_FOUND` / `AMBIGUOUS_ANCHOR` / `EVIDENCE_MISSING` / `CROSS_SPAN_EVIDENCE_MISSING` / `ACCEPTANCE_MISSING` / `DUPLICATE_ID`；
  - `REASON_CODES`：方案 §4.2 的逐项原因码 + 允许的下一步（界面/报告共用一份）。
- `public/revision-plan.js` 新增 `buildRevisionPlanV2` / `planAuthorizationV2` / `targetCandidates`
  - `reference` 证据只读，永不进入授权表；
  - `candidate_edit` 才是可申请编辑的目标；同一问题全部目标共用一个 `issue:<id>` 原子组；
  - 歧义/找不到/保护区/未批准 → 分别 `ambiguous_anchor` / `needs_scope` / `refused` / `authorization_missing`，**整条问题不进入候选**；
  - 授权表同时提供 `authorized`（v1 执行器读）与 `authorized_targets`（v2 语义），**指向同一张表**。
- `public/revision-semantic-verifier.js`
  - 确定性：证据按角色变化、必须保留项、授权外补丁、声称已改却无 diff、`unaccounted`、底稿哈希；
  - 全局校验：候选稿必须能由已记录补丁逐字重建（否则全部 `DIFF_MISMATCH`）；
  - 语义层（外部注入）：`pass/fail/need_context`；`not_run` 永不 pass；确定性 fail 与语义 pass 冲突 → `LAYER_CONFLICT`（待复核）。
- `public/revision-closure.js`
  - 状态机（含失败分支，禁止跳步）、逐条状态（scope/patch/safety/semantic/final 五字段分开）；
  - 指标：勾选 / 定位 / 补丁 / 门禁 / 语义通过 / 未解决，**补丁数不等于修复数**；
  - 结论：`BLOCKED` / `PARTIAL` / `VERIFIED_CANDIDATE` / `PERSISTED_VERIFIED`；
  - 预算用**整数分**（单笔 ≤200、累计 ≤200、轮次上限），未知费用一律不放行；幂等键与重放保护；
  - 二次复修队列只收"失败且仍在原授权范围"的问题，底稿/蓝图/保护区/授权问题交人处理。

## 三、接入与边界

### 3.1 服务端（只读为主）

- 迁移：`revision_selections` 新增 `closure_json`（默认空串，附加式）。
- `POST /api/novel/revision/closure-receipt`（作者通道；模型通道 403）
  - 只更新**本章最近一次选择记录**的 `closure_json`；不改勾选、不改正文、不新建记录；
  - 没有选择记录 → 404；非对象 → 400；>64KB → 413；`work_id` 不符 → 400。
- `GET /api/novel/revision/closure/status?chapter_id=`
  - 只读：不触发复修、不写库、不调用模型；返回模式、最近选择、回执与 `read_only:true`。
- 开关 `NOVELSTUDIO_REVISION_CLOSURE`：`off|diagnostics|full`，**默认 diagnostics**。
  - `off`：拒绝回执、状态如实返回 `enabled:'off'`；
  - `diagnostics`：允许回执/状态，**不开放**自动二次复修（默认）；
  - `full`：允许自动复修（本轮未实现自动触发，保留为后续接线位）。
- 架构上没做的事：没有新增写正文/自动提交端点。写回仍走原有"作者一次性审批 + 差异预览合并"。

### 3.2 前端

- `buildAIReviewPrompt`：新增 findings 契约（并保留 issues 兼容）。
- `reviewFindingsOf`：保留 `role/required/title/type/severity/explanation/acceptance`（旧报告默认 role=candidate_edit，保持既有行为）。
- `refineByChecklist`：有结构化证据时走 v2 计划；否则保持 v1（旧字符串清单行为不变）。
- 差异预览：覆盖表接收逐条结论；新增"质量闭环"真实计数块；标题/tost 改为"应用 N 个局部补丁"，不再写"已改好 N 处"。
- 新增「运行独立语义复验（一次付费调用）」按钮：作者显式触发，同一候选只允许一次；解析失败如实报错，不判通过。
- 回执在每轮修稿后尽力写入（失败只在控制台 warn，不阻断展示）。

### 3.3 DSH 插件（只读）

- 新增只读工具 `novel_revision_status`（能力表 `read_only`）：读取所选章的闭环状态与逐条原因；
- 明确不提供写回能力；`novel_chapter_save` 的一次性作者审批逻辑**未改**；
- `plugin.json` 的工具清单与端点清单同步更新（`verify-plugin-tools.mjs` 对账通过）。

## 六、本轮自查发现并修复的自身缺陷

这两处都是**本轮验证过程中由既有测试/冒烟抓出来的**，不是新功能的一部分：

1. **伏笔状态 CAS 把 NULL 当默认值，忽略存储默认空串（P01 遗留，真实 409）**
   - 现象：`POST /api/novel/foreshadows/:id/status` 对"新建时没显式写 `foreshadow_status`"的伏笔
     第一次更新返回 409「已被并发修改」。
   - 根因：`story_events.foreshadow_status` 的存储默认值是**空串**（业务语义=open），
     而 CAS 判据写成 `COALESCE(foreshadow_status,'open') = ?` —— 只把 NULL 当 open，空串不等于 'open'，
     UPDATE 恒 0 行 → 被误判成并发冲突。
   - 修复：按存储语义归一（`''` 与 `open` 同义），SQL 用 `CASE` 显式表达；
     新增 `.p1-baseline/test-1018-foreshadow-atomic.mjs` A2 回归（不传状态建伏笔 → 第一次更新 200）。
   - 为什么既有测试没抓到：`test-1018-foreshadow-atomic` 全部显式传 `foreshadow_status:'open'`，
     把生产默认值掩盖了；插件冒烟用的是真实默认值。**教训：测试数据要覆盖"不传字段"的路径。**

2. **插件冒烟把"异常定位文件"写死成 server.js（P05 抽取后过期）**
   - 现象：`日志：服务端接口异常（400 非法 JSON）入账并定位代码文件` 失败。
   - 根因：请求体解析已抽到 `ai/http/respond.mjs`，日志真实记录 `respond.mjs`；
     断言仍写 `includes('server.js')`。
   - 修复：断言改为"必须匹配 `server|respond.mjs` 的真实代码文件"，保留"能定位"的意图，
     不允许空值/占位字符串通过。

## 七、回滚

- 功能开关：`NOVELSTUDIO_REVISION_CLOSURE=off` → 回执被拒、状态如实返回 off；旧修稿路径不受影响。
- 代码回滚：`public/revision-{findings,semantic-verifier,closure}.js` 与 `test-1019-*` 可整批删除；`app.js`/`server.js`/`db.js` 的改动均按"附加式"设计（旧字段/旧路径默认不变）。
- 数据回滚：`closure_json` 只是附加列，旧代码忽略它，不影响历史选择记录。
- 不回滚：已经产生的章节历史版本与作者审批记录（按原机制保留）。
