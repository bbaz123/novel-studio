## 一、自动二次复修（源码内生效，默认开启）

**行为**：一次修稿产出候选后，对**逐条验收判定失败**（`verdict=fail`）的条目自动做定向复修，最多 2 轮；
每轮只重写这些条目、只在**作者原勾选集合**内改；最终候选仍停在差异预览，**写回正文必须作者点「合并到正文」**。

**安全与成本边界（写死在代码里）**：

- 只选 `verdict=fail` 且仍在原授权集合内、且不是硬阻塞（`CANON_CONFLICT` / `BASE_STALE` / `PROTECTED_SPAN` / `AUTHORIZATION_MISSING` / `LAYER_CONFLICT`）的条目；
- 每轮先算成本**上界**（CJK 字符按 1 token、输出按 `max_tokens` 上限、单价取保守值），
  超 `ns_revision_budget_cents`（默认 200 分）或**无法核价** → 不执行，并在预览/提示里写明原因（不静默跳过）；
- 每轮应用后重新跑安全门禁（组合核验）与逐条确定性验收，不沿用上一轮结论；
- 修完仍失败的条目如实留在覆盖表；候选稿永远不会因为"又跑了一轮"被写成已定稿。

**关闭方式**：`localStorage['ns_revision_auto_repair'] = '0'`。

**触发点**：① 首次修稿的确定性验收已有失败条目；② 作者点「运行独立语义复验」且语义判失败时（复修后再自动复验一次）。

## 二、P1 三项

### P1-1 词条版本化（`ai/story-state/entry-versioning.mjs`）

- 新表 `world_entry_versions`（追加式不可变版本）+ `world_entries.version`（当前指针，只增不减）；
- 每次保存写入新版本；回滚 = 恢复目标版内容 + **新增一版**（不删除历史）；
- 端点：`GET /api/novel/world_entries/versions?entry_id=`（只读）、`POST /api/novel/world_entries/rollback`（作者通道，模型 403）；
- 语义验收器新增 `ENTRY_VERSION_STALE`：引用版本 ≠ 当前版本时，不得按旧口径判冲突。

### P1-2 道具状态链（`ai/story-state/prop-chain.mjs`）

- 新表 `story_prop_states`：每次状态迁移绑定章节 + **本章正文逐字证据**（找不到/出现多处都拒绝登记）；
- 端点：`GET /api/novel/prop_chain?work_id=&prop_key=`（只读）、`POST /api/novel/prop_chain`（作者通道，模型 403）；
- 语义验收器新增 `PROP_STATE_MISMATCH` / `PROP_EVIDENCE_LOST`：最终状态不符或状态证据在候选里丢失 → 确定性失败。

### P1-3 伏笔自动登记（`ai/story-state/foreshadow-autoregister.mjs`）

- 审稿 `deferred` 中 `type=possible_foreshadowing`（或明确暗示词、且非否定句）自动登记为
  `story_event_proposals` 的 **pending 候选**；作者确认后才成为事件（**不写事件账本**）；
- 幂等去重（同 work 同归一化摘要只登记一次）+ 每章上限 10 条；
- 开关：`NOVELSTUDIO_FORESHADOW_AUTOREGISTER=0` 可关闭。

## 三、DSH 协调器（`dsh-auto-plan-executor/lib/writing/`）

7 个模块 + 单测（8 条，已并入该插件的 `npm test`）：

| 模块 | 职责 |
| --- | --- |
| `studio-adapter.js` | 只读调用 Studio 闭环状态；形状不对/非只读/连不上都抛结构化错误 |
| `review-normalizer.js` | 审稿 findings 归一化（缺证据/缺判据如实标注） |
| `acceptance-policy.js` | 逐条验收结论；语义未运行/未入库不得判 `PERSISTED_VERIFIED` |
| `quality-state.js` | 只读状态镜像（阶段映射、轮次、历史） |
| `cost-tracker.js` | 整数分预算；未知/非法/超限一律拒绝 |
| `quality-coordinator.js` | "读状态 → 判定 → 下一步"编排；不写 Studio、不代写正文 |
| `quality-reporter.js` | 只含真实计数的中文报告（候选稿 ≠ 已入库） |

边界：DSH 不注册写作工具、不写 Studio 账本；推进轮次只是请求 Studio 执行，写回仍走作者审批。

## 六、界面修复（v1.2.3，2026-10-18 报障）

1. **对照视图不再顶掉审稿报告**：`showRevisionComparison` 以 `stack:true` 打开；`openModal`/`closeModal`
   支持叠加栈，关闭对照后恢复上一层的审稿报告（`paintModal` 统一渲染）。
2. **修稿底稿自动恢复**：审稿保存时把 AI 当时看到的正文快照存进 `report.base_text`（PUT 与长任务回填两条路径）；
   `refineByChecklist` 底稿为空时按 `info.article → report.base_text → 当前章节正文` 恢复，
   三处都取不到才如实拒绝。
3. **写作区高度**：`.editor-content` 增加 `min-height:46vh`；`.chapter-state-panel` 限高 `28vh` 并自身滚动，
   章末状态面板再长也不挤掉正文书写区。

验证：`frontend-test` QC-18（叠加/恢复）、QC-19（底稿恢复顺序）、QC-20（CSS 下限/限高）；
`test-1020` A4（`base_text` 持久化并可读回）。
